# OCLR 直播 UI 空间布局规划 v1

> 本轮状态：第一轮审阅纠偏后的空间布局规划收束稿。赛事品牌、页面标题与广播画面统一为 **OCLR**；不接数据、不做最终主题、不使用背景图/动画/纹理/最终皮肤。
>
> 配套评审页：[index.html](./index.html) · 样式 [styles.css](./styles.css) · 交互 [app.js](./app.js)

## 1. 本轮范围与画布边界

- 赛事：**OCLR**。画面中央只出现 `OCLR · 阶段占位`，不出现参考赛事的赛事品牌。
- 六个核心场景：等待选手、Mappool Ban/Pick、Playing、单图结算、全场胜利、暂停/技术处理中。
- 上场人数 **4v4 / 3v3 未定案**；两种方案可在评审栏切换，评审栏注明未定案，不默认 1v1。
- 游戏源比例提供 **4:3（默认）/ 16:9** 两种评审选项，可在评审栏切换。窗口使用 contain：保持源比例，不裁切、不拉伸。
- 本轮只使用示例数据；队名、选手、谱面、比分、星位、聊天均为占位。
- Playing 底部队分区改为**一体比分区**：固定中线端点，实心分差带向左/右改变长度；两端比分跟随带的端点，平分归零。此前“固定长度小胶囊在轨道上整体平移”的方案已废弃并移除。演示不连接数据，也不推断比分公式。
- 无外部字体、图片素材、外部依赖、动画、渐变或纹理。

### 1.1 画布内 / 画布外职责

**画布内只放观众需要看的内容：**赛事与阶段、队伍、系列赢图位、等待/到场/就绪、谱面与状态、比分、当前谱面与参数、暂停状态、单图与全场结果、聊天、玩家人名和游戏画面占位。

**画布外保留评审说明：**入口按钮、场景切换、4v4/3v3、游戏源比例、等待/图池演示、干净输出、键盘提示，以及下列设计说明：

- 全部到场不等于 ready；就绪需要独立确认状态，演示不会自动触发。
- 3v3 下排两侧留白是构图保留，不是掉线位。
- Mappool 只展示已有状态与队属，不推断正式行动顺序或规则。
- 单图结算不是全场胜利；两者不共用主标题，也不自动切换。
- 暂停时间未知时不编造倒计时，不自动返回原场景。
- 本页不是正式结果、数据或控制台。

画布上只保留一处极小文字标记：**布局示意**。政策、数据来源、接入方式、测试说明和尺寸/留白解释不再做成直播面板。

## 3. 全局画幅与层级

```text
┌──────────────────────────────────────────────────────────────┐
│ 顶部锚点 180px：示例A队 / OCLR·阶段占位 / 示例B队              │
├──────────────────────────────────────────────────────────────┤
│ 主体 720px                                                   │
├──────────────────────────────────────────────────────────────┤
│ 低位观众信息 180px                                            │
└──────────────────────────────────────────────────────────────┘
                       1920 × 1080
```

- 顶部左/右队伍与系列赢图星位固定，中央为赛事/阶段与当前场景；切换场景时顶部锚点不跳动。
- 赢图星位只用空心占位；星位数量、赛制、正式结果均未接入，也未从其他赛季补填。
- 状态不以颜色单独表达；到场、禁用、选用、胜负均有文字或符号。
- 低位 180px 只放观众信息：
  - 等待：现场解说、当前阶段、本场对阵；
  - Mappool：聊天；
  - Playing：比分与向外生长的分差带、当前谱面/参数；
  - 单图结算、全场胜利、暂停：只放相应的比分、谱面或结果占位，不放政策说明。

## 4. 六个核心场景与切换关系

```text
等待选手 ──→ Mappool Ban/Pick ──→ Playing ──→ 单图结算
                                             │
                                             ├─→ 继续下一图
                                             └─→ 全场胜利

Playing / 等待 / Mappool 等 ──→ 暂停 / 技术处理中
                              ←── 人工恢复后回到原场景

注：这是评审页的画面关系，不是正式规则或行动顺序。
```

| 场景 | 观众看到的主问题 | 主体内容 | 低位观众信息 |
| --- | --- | --- | --- |
| 等待选手 | 谁到了、是否就绪 | 左右上场槽位、对阵、到场人数、就绪状态 | 现场解说 / 当前阶段 / 本场对阵 |
| Mappool Ban/Pick | 这些谱面现在什么状态 | 三列谱面胶囊、文字状态与队属 | 聊天 |
| Playing | 谁在打哪张图、比分如何 | 8 个或 6 个 POV 游戏窗、当前比分与谱面 | 两端比分 / 分差带 / 当前谱面与参数 |
| 单图结算 | 这一张图谁赢 | 与 Playing 相同的 6/8 路窗口，游戏源内是原生结算占位 | 两队队伍总分 / 固定最终分差带 / 本图谱面 |
| 全场胜利 | 系列赛谁获胜 | 全场胜者、最终赢图占位 | 全场胜者 / 系列星位 / 对手 |
| 暂停 / 技术处理 | 比赛为何停、何时恢复 | 中断状态、恢复时间未确认 | 比赛状态 / 恢复时间 / 当前谱面 |

## 5. 逐场景说明

### 5.1 等待选手

本轮重点场景。

- 顶部中央显示 `等待选手 · 4v4` 或 `等待选手 · 3v3`。
- 中部左右对称显示本场上场槽位：
  - 4v4：每队 2×2，共 4 个上场槽位；
  - 3v3：每队上 2、下 1 居中；
  - 只渲染本场槽位，不把全队名单当成同时上场人数。
- 每张选手卡包含：槽位号、选手示例名、到场状态（等待中 / 已到场）、就绪状态（未确认）。到场和就绪是两个独立状态。
- 中央 VS 区显示双方对阵、已到场人数、当前主状态和就绪徽标。**双方全部到场也不会自动把就绪变成已确认**；这解释保留在画布外与本文档，不再作为字幕面板出现。
- 低位改为纯观众信息：现场解说、当前阶段、本场对阵。
- 3v3 的空白保留在画布内但不在画面内解释；解释放在评审栏与本文档。

### 5.2 Mappool Ban/Pick

- 顶部锚点沿用，中央阶段为 Mappool Ban/Pick。
- 主体三列谱面胶囊列表，每列 6 条；每行只放编号、谱面标题占位、作者/难度占位、状态徽标。
- 状态为 `未选` / `禁用 · 示例A队` / `选用 · 示例B队`；队属写在文字里。
- 画布内不再放状态图例、规则声明或“现在轮到谁”等说明。状态与队属为演示值，正式行动顺序、轮次和规则不在本轮推断。
- 下方 180px 保持聊天区域；聊天内容是占位，不复刻参考样式。

### 5.3 Playing

#### 画面结构

- 顶部 180px 保持赛事/队伍锚点；**Playing 主体不再增加场景大标题行**。
- 720px 主体几乎完整留给游戏窗：
  - 4v4：4 列×2 行，共 8 格；左两列示例A队，右两列示例B队，每队 2×2；
  - 3v3 候选：每队上 2、下 1 居中，共 6 格；保留原 4 列基础网格和同样的窗口尺寸。
- 每个 POV 使用近 4:3 外框，内部是游戏源显示区。底部只有一条 24px 的选手标签，不设置额外标题、说明、音频状态或脚注。
- 底部 180px 独立放比分、分差带、当前谱面与参数；分差带贴住游戏区下缘，不覆盖游戏画面。底部不再重复大幅队名。与评审栏的 4:3 / 16:9 选择联动，窗口本身保持稳定尺寸。

#### 游戏源比例与 contain

评审栏提供 **4:3（默认）/ 16:9** 切换，写在 URL 的 `source` 状态里。源窗口未知时可以改选。

- 4:3：游戏源以 4:3 contain 到窗口内，外框接近 4:3。
- 16:9：游戏源以 16:9 contain，窗口上下留出灰白 letterbox，不拉伸成 4:3，也不裁切左右。
- 外框与源窗口的比例一致时，源画面尽量放大；不一致时以最长边贴合并居中，保持完整画面。
- 灰白框内只写“游戏画面占位”；不显示“不裁切/16:9/布局尺寸”等实施说明。
- 游戏源内容的大小优先于加入额外标题；8 个窗口占满主体高度。

#### 一体比分区

按新增真实截图重新定稿；**此前固定长度小胶囊在独立轨道上整体平移的方案已废弃并从画布/CSS 移除。**

- 分差带直接位于 8 窗游戏区下缘、谱面信息条上方，不再另起一条细轨道，也不使用大块队名表格。
- 固定端是画布水平中线；带只向领先方向生长，另侧不出现轨道。平分时长度归零。
- 实现：`.score-fill` 固定 CSS 宽 `300px`、`left: 50%`、`transform-origin: 0 50%`；只过渡 `transform`。五个演示态的 `scaleX` 为：
  - 左小领先 `-0.266667`（视觉宽 80px）；
  - 左大领先 `-1`（视觉宽 300px）；
  - 平分 `0`（视觉宽 0）；
  - 右小领先 `+0.266667`（视觉宽 80px）；
  - 右大领先 `+1`（视觉宽 300px）。
- 负值向左、正值向右；方向反转时按 300 → 0 → -300 的同一缩放轴经过中线，固定端始终在中线，不会整条跳过中线。
- 领先分数靠近带的外端下方，字号更大；落后分数在中线另一侧靠内，字号更小、灰度更轻。两侧用小型 `A` / `B` 标签识别，不重复顶部队名。
- 平分时两端分数等大、关于中线对称；条长为 0，中线锚点保留。
- 演示值：基础双方各 `1,000,000`；小领先方 `1,050,000`；大领先方 `1,400,000`。这些是本地示意值，不是正式比分，也不用于推导长度公式。
- 评审栏提供 **左小领先 / 左大领先 / 平分 / 右小领先 / 右大领先** 五态；端点距离只用于示意，不做正式归一化。
- 仅保留必要短过渡；`prefers-reduced-motion: reduce` 下取消。无背景动画。

#### 3v3 与 4v4

- 4v4 是参考录像最接近的方案；也是当前默认评审状态。
- 3v3 候选保留每队 2×2 骨架和相同画面尺寸，下排单窗居中，两侧留白不在画布内解释，但必须由评审栏/本文档明确标为构图保留，而不是掉线槽。
- 最终采用 4v4 还是 3v3 仍需用户决定。

### 5.4 单图结算

- 复用 Playing 的窗口骨架：4v4 每队 4 窗、共 8 窗；3v3 每队 3 窗、共 6 窗，沿用上 2 下 1 居中。窗口位置、尺寸和 4:3 / 16:9 源比例与 Playing 相同，所有上场选手窗口全部可见、不滚动。
- 每窗保留选手名标签。灰色游戏源内部只写两行占位：
  - `osu!原生结算画面`
  - `Accuracy · Score · 100 · 50 · Miss`
- 这是布局占位，不是真实截图，也不仿造 osu 原生控件、皮肤或逐人假数据。与用户澄清一致：**不使用自制逐人成绩表**。
- 下方延续 Playing 结构：
  - 一体比分区的 A/B 读数改为“队伍总分”；
  - 保留固定最终分差带；
  - 下方继续显示“本图谱面”和参数占位。
- 固定演示分（独立于 Playing 的领先按钮）：
  - 示例A队：`350000 / 320000 / 300000 / 280000`；
  - 示例B队：`330000 / 310000 / 290000 / 260000`；
  - 4v4 全四人合计：A `1,250,000`，B `1,190,000`；
  - 3v3 只合计前三人：A `970,000`，B `930,000`。
- 最终分差带使用固定的 A 领先示意，不随 Playing 的领先状态按钮变化；正式比分映射仍待接入。
- 单图结算仍不是全场胜利，也不自动切换到全场胜利。

### 5.5 全场胜利

- 标题为“全场胜利”，主体突出示例A队为全场胜者，右侧保留最终赢图占位。
- 下方只放本场对手、上场方案、系列星位、下一张图（无）等观众信息。
- 不使用单图统计卡，不重复单图结算内容。
- 正式赛果、星位数量和赛制仍未接入；这些限制只写在本文档与评审栏。

### 5.6 暂停 / 技术处理中

- 主体显示暂停符号、比赛暂停、恢复时间未确认。
- 侧区只放当前对局、当前比分、当前谱面、系列赛占位。
- 不显示倒计时、原因、责任方、接入或来源说明；未知时间不编造数字。
- 恢复后的人工返回只作为评审流程，不在画布上解释。

## 6. 画布外评审控制

- 场景按钮：六个核心场景，每次只显示一个。
- 上场人数：4v4 / 3v3，标记未定案。
- 游戏源比例：4:3 / 16:9，默认 4:3；窗口 contain，不裁切、不拉伸。
- 等待演示：全部等待 / 示例A队到场 / 双方到场。双方到场后就绪仍为未确认。
- 图池演示：焦点谱面在未选、禁用、选用之间切换；不推断正式流程。
- 比分演示：左小领先 / 左大领先 / 平分 / 右小领先 / 右大领先，只影响 Playing 的一体比分示意；不计算比分、不推导公式。
- 干净输出：隐藏评审栏，只保留画布和一处“布局示意”。
- 键盘：`1–6` 切场景，`C` 切换干净输出，`Esc` 退出干净输出。

### 6.1 URL 恢复

评审页把状态写入 URL，刷新或重开可恢复：

```text
index.html?clean=1&mode=3v3&source=16x9#playing

index.html#scene=playing&mode=4v4&source=4x3&lead=left-large&clean=1&arrival=both&map=picked
```

字段：

- `scene`：`waiting` / `mappool` / `playing` / `map-result` / `victory` / `pause`
- `mode`：`4v4` / `3v3`
- `source`：`4x3` / `16x9`
- `lead`：`left-small` / `left-large` / `equal` / `right-small` / `right-large`；旧值 `left`/`right` 兼容映射到 `left-small`/`right-small`
- `clean`：`1` / `0`
- `arrival`：`none` / `a` / `both`
- `map`：`open` / `banned` / `picked`

URL 只恢复本地评审状态，不携带凭证、不请求赛事 API、不连接 tosu。

## 7. 后续可选场景（仅建议，本轮未实现）

1. **开播倒计时**：只在来源时间明确时显示数字；未知时写“开播时间待定”，不编造。布局可占主画面中央，保留顶部 OCLR 锚点。
2. **赛程 / 对阵**：用于开播前或场间，展示今日赛程或下一场对阵；不填充历史结果。
3. **图池 Showcase**：大图展示谱面与分类，不与 Ban/Pick 状态混用；不接封面图片。
4. **收播**：静态收束画面，可放感谢与下一场时间待定；不自动结束直播，不编造结果。

这些场景不进入本轮六个核心按钮。

## 8. 待定项

1. **4v4 还是 3v3** 为最终上场人数。
2. 3v3 采用当前“上2下1居中”还是改为 3×2 全铺满；当前仅实现前者。
3. 游戏源最终常见比例：4:3 / 16:9 或混合。当前默认 4:3，可切换；最终资产类型确定后再锁定。
