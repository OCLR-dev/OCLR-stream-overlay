## 1. 本轮范围与画布边界

- 赛事：**OCLR S11**；顶部固定锚点显示 `OCLR S11`、当前阶段、BO11 先 6 / BO13 先 7、当前普通/EX/TB，以及双方 6/7 个赢图星位。
- 六个核心场景：等待选手、Mappool Ban/Pick、Playing、单图结算、全场胜利、暂停/技术处理中。
- 常规上场人数 **3v3 / 4v4 未定案**；两种方案独立切换。用户于 **2026-10-27（America/New_York）** 确认：EX 激活时双方各减 1 路，常规 3v3→EX 2v2、常规 4v4→EX 3v3；清除 EX / TB 恢复常规人数。最终常规人数仍未确定。
- 游戏源比例提供 **4:3（默认）/ 16:9** 两种评审选项，可在评审栏切换。窗口使用 contain：保持源比例，不裁切、不拉伸。
- 本轮只使用示例数据；队名、选手、谱面、比分、星位、Ban/EX 状态、聊天均为占位。
- Playing 底部继续使用一体比分区：固定中线端点，实心分差带向左/右改变长度；此前“固定长度小胶囊在轨道上整体平移”的方案已废弃并移除。
- 无外部字体、图片素材、外部依赖、动画、渐变或纹理。

### 1.1 画布内 / 画布外职责

**画布内只放观众需要看的内容：**赛事/阶段/BO、队伍、系列赢图位、等待/到场/就绪、谱面与状态、比分、当前谱面与参数、EX 开启队伍与剩余次数、Ban 槽、暂停类型、单图与全场结果、聊天、玩家人名和游戏画面占位。

**画布外保留评审说明：**场景切换、常规 3v3/4v4、阶段、谱面类型（普通/TB）、游戏源比例、系列星位人工演示、EX 开启方与次数、Ban 槽演示、暂停演示、干净输出、键盘提示。S11 高级演示收在可折叠抽屉里，默认收起以免压缩画布。

- 全部到场不等于 ready；就绪需要独立确认状态，演示不会自动触发。
- 3v3 下排两侧留白是构图保留，不是掉线位。
- Mappool 只展示本地状态与队属，不推断正式行动顺序；Ban 槽演示不是完整 BP 引擎。
- 单图结算不是全场胜利；两者不共用主标题，也不自动切换。
- 暂停时间未知时不编造倒计时，不自动返回原场景。
- 本页不是正式结果、数据或裁判工具。

画布上只保留一处极小文字标记：**布局示意**。政策、数据来源、接入方式、测试说明和尺寸/留白解释不做成直播面板。

## 5. 逐场景说明

### 5.1 等待选手

- 本场槽位由常规 3v3/4v4 与当前 EX 状态共同决定：常规 3v3 的 EX 为 2v2，常规 4v4 的 EX 为 3v3；A/B 任一方开启 EX 时双方都减 1 路。
- 中部左右对称显示本场上场槽位：
  - 4v4：每队 2×2，共 4 个上场槽位；
  - 3v3：每队上 2、下 1 居中；
  - 只渲染本场槽位，不把全队名单当成同时上场人数。
- 每张选手卡包含：槽位号、选手示例名、角色（Captain/T1/T2/T3）、到场状态、就绪状态。到场和就绪是两个独立状态。
- 中央 VS 区显示双方对阵、已到场人数、当前主状态和就绪徽标。**双方全部到场也不会自动把就绪变成已确认。**
- 低位只放观众信息：现场解说、当前阶段、本场对阵。
- 常规窗口显示 Captain/T1/T2/T3；EX 示例窗口只用后排合成标签 T2/T3（3v3 基础）或 T2/T3/T4（4v4 基础），不显示 Captain/T1。无真实阵容选择器或身份匹配。

### 5.2 Mappool Ban/Pick

- 主体三列谱面胶囊列表，每列 6 条，谱面行带 NM/HD/HR/FM/TB 模组占位。三列与聊天保持。
- 顶部新增 S11 状态条：
  - A/B 各 2 个 Ban 槽，区分 `未确认` / `空Ban` / 已选 mod；
  - 双方 EX 剩余次数 0/1/2；
  - 先 Pick / 先 Ban 的独立人工状态；
  - 当前普通/EX/TB 和当前图 EX 开启队伍。
- EX 状态条使用约 18px 的开启队伍标记、18px 的剩余次数标签和 22px 的数字；Ban/顺序文字不小于 16px。状态条加高至约 92px，谱面列表行高相应收缩，但仍在 720px 主体内完整显示。
- 谱面状态为 `未选` / `禁用 · 示例A队` / `选用 · 示例B队`；队属写在文字里。
- 画布内不放状态图例、规则长文或“现在轮到谁”的推断。Ban 槽是可人工演示的本地状态，不是完整 BP 引擎。
- 本地 Ban 校验：同队两次 Ban 不得同 mod（NM/FM 例外）；TB 不可 Ban。校验反馈在画布外，不自动改谱面状态或写结果。
- EX 是人工确认后的状态：未开启 / 示例A队开启 / 示例B队开启；TB 禁 EX。开启后 Playing/等待/结算按有效人数减 1，但不会自动扣剩余次数或改变星位。
- 下方 180px 保持聊天区域；聊天内容是占位，不复刻参考样式。

### 5.3 Playing

#### 画面结构

- 顶部 180px 保持赛事/队伍锚点；**Playing 主体不增加场景大标题行**。
- 720px 主体几乎完整留给游戏窗：
  - 常规 4v4（8 格）：4 列×2 行；左两列示例A队，右两列示例B队，每队 2×2；
  - 常规 3v3 或 EX 3v3 基础（6 格）：每队上 2、下 1 居中，保留原 4 列基础网格和同样的窗口尺寸；
  - EX 2v2（常规 3v3 开启 EX，4 格）：每队 2 窗并排，两队之间留中央分隔，整行在 720px 主体内垂直居中；单窗尺寸与 4v4 的 1/4 宽、半高高窗相近，源仍按 contain。
- 每个 POV 使用近 4:3 外框，内部是游戏源显示区。底部只有一条 24px 的选手标签，显示选手名与角色，不设置额外标题、说明或音频状态。
- 底部 180px 独立放比分、分差带、当前谱面与参数；分差带贴住游戏区下缘，不覆盖游戏画面。切换 4:3 / 16:9 时窗口本身保持稳定尺寸，源画面 contain。

#### 谱面附近信息

- 谱面信息条显示当前 `普通/EX/TB`、当前模组（NM/HD/HR/FM，TB 时显示 TB）和 EX 开启队伍。
- EX 开启队伍使用约 18px 的显式文本：`EX · 示例A队开启`、`EX · 示例B队开启` 或 `EX 未开启`；TB 时显示 `TB · 禁 EX`。
- FM 时显示必要要求：`FM · 每队至少 1 名单HD（含 EZ/HDEZ） + 1 名单HR`。
- EX 标记同时触发有效人数/窗口切换：A/B 开启方对双方窗口影响相同；清除 EX / TB 恢复常规窗口。结算总分随有效人数取样，EX 标签不会单独改分。

#### 游戏源比例与 contain

- 评审栏提供 **4:3（默认）/ 16:9** 切换，写在 URL 的 `source` 状态里。
- 4:3：游戏源以 4:3 contain 到窗口内，外框接近 4:3。
- 16:9：游戏源以 16:9 contain，窗口上下留出灰白 letterbox，不拉伸成 4:3，也不裁切左右。
- 外框与源窗口比例一致时源画面尽量放大；不一致时以最长边贴合并居中，保持完整画面。

#### 一体比分区

- 分差带位于游戏区下缘、谱面信息条上方，不另起细轨道，不使用大块队名表格。
- 固定端是画布水平中线；带只向领先方向生长，另侧不出现轨道。平分时长度归零。
- 实现：`.score-fill` 固定 CSS 宽 `300px`、`left: 50%`、`transform-origin: 0 50%`；只有 `transform` 过渡。五态 `scaleX`：
  - 左小领先 `-0.266667`（视觉宽 80px）；
  - 左大领先 `-1`（视觉宽 300px）；
  - 平分 `0`（视觉宽 0）；
  - 右小领先 `+0.266667`（视觉宽 80px）；
  - 右大领先 `+1`（视觉宽 300px）。
- 负值向左、正值向右；方向反转时按 300 → 0 → -300 的同一缩放轴经过中线，固定端始终在中线。
- 领先分数靠近带的外端，字号更大；落后分数在中线另一侧靠内，字号更小、灰度更轻。两侧用小型 `A` / `B` 标签识别，不重复顶部队名。
- 平分时两端分数等大、关于中线对称；条长为 0，中线锚点保留。
- 演示值：基础双方各 `1,000,000`；小领先方 `1,050,000`；大领先方 `1,400,000`。这些是本地示意值，不是正式比分，也不用于推导长度公式。
- 评审栏提供 **左小领先 / 左大领先 / 平分 / 右小领先 / 右大领先** 五态；不计算或归一化正式比分。

### 5.4 单图结算

- 复用 Playing 的有效窗口骨架：常规 4v4 共 8 窗；常规 3v3 / EX 3v3 共 6 窗；EX 2v2 共 4 窗。窗口位置、尺寸和 4:3 / 16:9 源比例与 Playing 逐窗一致，所有有效上场窗口全部可见、不滚动。
- 每窗保留选手名与角色标签。灰色游戏源内部只写两行占位：
  - `osu!原生结算画面`
  - `Accuracy · Score · 100 · 50 · Miss`
- 这是布局占位，不是真实截图，也不仿造 osu 原生控件、皮肤或逐人假数据。**不使用自制逐人成绩表。**
- 下方延续 Playing 结构：
  - 一体比分区的 A/B 读数改为“队伍总分”；
  - 保留固定最终分差带；
  - 下方继续显示“本图谱面”和参数占位；
  - 与 Playing 一样显示当前普通/EX/TB、模组、FM 要求和 EX 开启队伍。
- 固定演示分（独立于 Playing 的领先按钮）：
  - 示例A队：`350000 / 320000 / 300000 / 280000`；
  - 示例B队：`330000 / 310000 / 290000 / 260000`；
  - 常规 4v4 全四人合计：A `1,250,000`，B `1,190,000`；
  - 常规 3v3 或 EX 3v3 只合计前三人：A `970,000`，B `930,000`；
  - EX 2v2 只合计前两人：A `670,000`，B `640,000`。
- 结算总分只按当前有效上场人数取现有数组前 N 项；常规 3v3/4v4 原值保留，EX 2v2/3v3 分别取前 2/3 项。最终分差带使用固定的 A 领先示意，不随 Playing 领先状态按钮变化；正式比分映射仍待接入。
- 单图结算仍不是全场胜利，也不自动切换到全场胜利。

### 5.5 全场胜利

- 标题为“全场胜利”，主体显示**全场胜者待确认**，不写示例队为正式冠军。
- 右侧保留最终赢图占位；下方显示赛制目标（BO11 先 6 / BO13 先 7）、当前阶段、常规人数和下一张图（无）。
- 顶部系列星位可人工演示，但全场胜利不根据星位自动产生冠军、不自动加星、不自动切换场景。
- 不使用单图统计卡，不重复单图结算内容。正式赛果仍未接入。

### 5.6 暂停 / 技术处理中

- 场景区分**战术暂停**与**技术处理中**。
- 战术暂停：显示暂停符号、`战术暂停`、`暂定 3:00`、`恢复时间：未确认`，并显示双方各 1 次战术暂停可用/已用状态。
- 技术处理：主标题为 `技术处理中`，显示恢复时间未确认；始终不自动消耗战术暂停。
- 侧区放暂停类型、双方战术暂停可用状态、断线重赛机会的人工确认状态、当前谱面。
- 不显示自动倒计时、原因推断、自动 FF/重赛/胜负或来源说明。30 秒后重赛机会须人工确认；未知时间不编造数字。

## 6. 画布外 S11 评审控制

顶部固定核心控制：

- 常规人数：4v4 / 3v3，标记最终待定。
- 阶段：小组赛 / 淘汰赛 / 决赛；联动 BO11 先 6 / BO13 先 7、星位上限 6/7。
- 谱面类型：普通 / TB；TB 会清除并禁用当前 EX 标记。
- 游戏源比例：4:3 / 16:9，默认 4:3。
- 场景：六个核心场景；`1–6` 切场景。

可折叠 S11 演示抽屉（默认收起）：

- 系列星位：A/B 人工星数，默认未知空星；选项随阶段上限变化。
- 谱面模组：NM / HD / HR / FM；EX 开启方：未开启 / 示例A队 / 示例B队。
- EX 剩余：A/B 各 0/1/2，人工设置；不自动扣减。
- 先 Pick / 先 Ban：分开人工设置，默认未确认。
- Ban 槽：双方各 2 个，选项含未确认 / 空Ban / NM / HD / HR / FM；TB 选项禁用。重复同 mod（NM/FM 例外）会阻止并给出反馈。
- 暂停演示：战术暂停/技术处理、A/B 战术暂停可用/已用、A/B 重赛机会人工确认。
- 画面演示：等待到场、Playing 五态领先、Mappool 焦点状态。
- 干净输出：隐藏评审栏，只保留画布和“布局示意”。
- 键盘：`1–6` 切场景，`C` 切换干净输出，`Esc` 退出干净输出。

外置控件不改变正式数据，不推断完整 BP 行动顺序，不做 EX 首 Pick/对方 Pick 裁判引擎。

### 6.1 URL 恢复

评审页把本地评审状态写入 URL，刷新或重开可恢复。旧式 `mode` 仍表示常规人数，不是 EX 模式：

```text
index.html?clean=1&mode=3v3&source=16x9#playing

index.html#scene=mappool&mode=4v4&source=4x3&stage=group&maptype=normal&mod=FM&exTeam=a&exA=1&exB=0&starA=2&starB=1&pickFirst=a&banFirst=b&banA1=NM&banA2=NM&banB1=empty&banB2=unknown&pauseType=tactical&tacticalA=available&tacticalB=available&rematchA=unknown&rematchB=unknown
```

字段：

- `scene`：`waiting` / `mappool` / `playing` / `map-result` / `victory` / `pause`
- `mode`：`4v4` / `3v3`（常规人数）
- `source`：`4x3` / `16x9`
- `lead`：五态比分演示；旧值 `left`/`right` 兼容映射到 `left-small`/`right-small`
- `clean` / `arrival` / `map`：原有评审状态
- `stage`：`group` / `elimination` / `final`
- `maptype`：`normal` / `tb`
- `mod`：`NM` / `HD` / `HR` / `FM`
- `exTeam`：`none` / `a` / `b`
- `exA` / `exB`：`0` / `1` / `2`
- `starA` / `starB`：`unknown` 或 `0`–`6/7`（由阶段上限校验）
- `pickFirst` / `banFirst`：`unknown` / `a` / `b`
- `banA1` / `banA2` / `banB1` / `banB2`：`unknown` / `empty` / `NM` / `HD` / `HR` / `FM`
- `pauseType`：`tactical` / `technical`
- `tacticalA` / `tacticalB`：`available` / `used`
- `rematchA` / `rematchB`：`unknown` / `available` / `used`

URL 只恢复本地评审状态，不携带凭证、不请求赛事 API、不连接 tosu。
