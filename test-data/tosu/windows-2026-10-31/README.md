# Windows tosu 实机采样：贡献者与 code agent 使用说明

本数据用于 UI 开发及异常状态检查。来源是 2026-10-31 Windows 现场采集的 10 分钟 tosu **字段投影**，共 3921 个有效帧，不是完整 WebSocket 原包，也不是整场比赛。已移除连接内网地址；非零选手账号 ID 替换为稳定测试 ID，原来的 0 保持为 0。时间、谱面 ID、队分、个人分、命中统计和事件顺序保留。不要用测试 ID 查询真实选手。

## 快速使用

以下命令均从仓库根目录执行，需要 Node.js 22.13+。

```sh
# 只校验数据 SHA256、帧数并打印关键时间线；无需安装依赖或启动服务
node tools/tosu-diagnostics/replay-public.js

# 首次安装并构建 UI
npm ci
npm run build

# 启动隔离 UI 回放，打开终端打印的 /control 与 /overlay 地址
node tools/tosu-diagnostics/replay-public.js --serve
```

使用随机本机端口和临时比赛存储，不读取 `.env.local` 或 OCLR 凭证，不修改日常 `.local/session.json`。Ctrl+C 退出；再次运行从头开始。脚本没有恢复真实赛事配置：比赛、图池和 BP 是明确的离线合成夹具，与采样中的 HR2/DT1 不匹配，不可当作真实图池或赛果。普通只读历史赛事模式仍使用仓库 README 中的 `npm run sim` 流程。

启动后留 5 秒打开页面，随后按原时间间隔广播数据。回放结束保持最后一帧，不补造 DT1 结算。需要快速浏览可用 `--serve --speed=10`；加速改变实际稳定等待时间，**只能用于视觉浏览，不能用于结算正确性验证**。不要在模拟器面板执行 reset/demo；本脚本直接控制回放帧。

UI 变更后重新 `npm run build`，重启回放，打开新打印的地址。回放传输经过真实 WebSocket、当前 TosuClient、归一化、共享会话及 SSE，页面使用当前代码。它重建了 v2 外壳和匿名队名，但未补造缺失的谱面参数、聊天、姓名、图片等。页面可能从现有封面逻辑请求 osu! 公共资源；这不是采集到的背景图片，也不是完全断网验证。离线时检查缺图状态。

## 已观察到的问题与关键时间线

时间相对于第一帧；原始 UTC 时间为 12:20:08.476Z 至 12:30:08.352Z。

| 相对时间 | 实机观测 | UI 与 agent 应检查的行为 |
| --- | --- | --- |
| 0 秒 | HR2（4556723）已在 Playing，6 个有效选手 | 支持中途加入；不能假设看到了开打前基线或已有 BP |
| 149.497 秒 | IPC 从 3 到 4（Ranking） | 保持 Playing 布局承载 Ranking；窗口位置与尺寸稳定 |
| 164.681 秒 | 仍为 Ranking，scoreVisible 关闭，总分清零 | 这是已知故障触发数据：不要把隐藏后的 0 当成新最终成绩、覆盖结果或反复计胜；检查总分保留至回图池 |
| 189.941 秒 | 返回房间 IPC 1，有效选手数变为 4 | 选手缺失与回房间不能造成布局跳动或伪造新赛果 |
| 299.302 秒 | 换到 DT1（1624401），有效选手 ID 暂时全为 0 | 已知故障触发数据：不应因暂缺选手 ID 而一直保留旧图；不能凭 0 ID 猜名单 |
| 445.644 秒 | DT1 开打，6 个有效选手 | 检查新图及队分更新；录制结束仍在 Playing，没有最终结果 |

前两项故障触发序列在历史归档中用于修复对照；它们的存在不等于当前 main 仍有同样缺陷。本包用于重现输入，**没有包含旧版本观察器或原始比赛快照**，默认 UI 回放也不声称重现当时 HR2 的完整自动判定基线。若需要验证计胜，应另建明确标注的隔离前置会话，保留缺少约两分钟现场连续性的事实，不能把重建基线说成实录。

## 数据限制

- 起点已在 HR2 游戏中，终点仍在 DT1 游戏中；只有完整的 10 分钟录制段，没有完整比赛或完整两局。
- 没有原始聊天、BG 图片字节、MOD、完整谱面参数、姓名、准确率、combo 等全部 v2 字段；不能据此验收 Chat、背景、HR/DT 参数或完整选手卡。缺失不是 0，也不能拿其他帧或模拟值冒充实测。
- 未提供各选手 finished 标记，也没有上游字段刷新时间。IPC Ranking、队分稳定或个人分加总一致，均不能单独证明所有人已结束。
- 此段无法覆盖所有卡顿、Panic、断连、撤回、TB、EX、Winner 等流程；这些需要另用模拟器与专项测试。本数据也不能证明真实 OBS 捕获、Windows 时序或直播结算全部可靠。
- 匿名化仅替换账号标识并移除地址，实际分数和谱面序列保留；不要称其为合成比赛或完整原包。

## 给贡献者的 code agent

1. 先读根目录 `AGENTS.md`、`README.md`、`DESIGN.md`；UI 在 `ui/`。保持当前操作合同，不修改游戏结算语义来迁就视觉效果。
2. 首先执行校验命令；`frames.ndjson` 是基线证据，不直接编辑。`manifest.json` 保存公开文件的 SHA256；原始私有归档不在仓库内。不要加入凭证、真实账号映射、现场会话或本地备份。
3. 观察 1920×1080 的 `/overlay` 和 `/control`。游戏捕获区保持纯绿，禁止动画或装饰侵入；保留稳定槽位 key。分数更新、重连或加载不能重复触发动效。明确区分实际观测、重建外壳、合成赛事和缺失数据。
4. 检查 `npm run check`、`npm run build`；改动业务逻辑时运行相关测试及 `npm test`。提交说明附关键状态截图、验证范围与未验证项。回放通过不等于实机联调通过。

## 文件

- `frames.ndjson`：逐行 JSON；header / connection / frame / stop 等记录，保留事件时间与 elapsedMs。
- `manifest.json`：来源、匿名化变更、帧数、记录数和公开文件 SHA256。
- `tools/tosu-diagnostics/replay-public.js`：从仓库根目录定位见上方命令；校验及隔离 UI 回放入口。
