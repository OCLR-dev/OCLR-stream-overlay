# 本图异常、重赛与观战恢复

日期：2026-10-28（America/New_York）。已实现本机流程与模拟用例；真实 osu!tourney / tosu / OBS 时序仍需直播机验证。

## 三类状态分开处理

| 情况 | 本机处理 | 恢复路径 |
| --- | --- | --- |
| 已 Pick，尚未 Playing，卡住后取消启动 / `!mp abort` | 保留同一轮准备图、Pick 方、BP 队列和 EX；没有开打 ID，不记成绩，不增加重赛局次 | 继续等待本图开打 / 保留原图重新准备 |
| 已开打后 abort，或选手掉线等待裁判决定 | 挂起自动推进和计胜，保留原开打记录；不自动判重赛、不扣重赛机会 | 裁判确认重赛后作废原尝试并建立关联的新尝试，等新的 Playing 建立新 run ID |
| 观战窗口故障、Panic、tosu 连接断开 | 记录观战异常，比赛是否继续待人工核对；不因为直播端重建而作废比赛 | 本图有效 Playing 恢复后人工确认继续原 run；若恢复时已结束，核对实际成绩后人工记录 |

osu! 官方文档说明 [Panic 会重新初始化所有 osu! 观战实例](https://osu.ppy.sh/wiki/en/osu%21_tournament_client/osu%21tourney/Spectator_usage)。它本身不能证明比赛房间 abort、玩家退出或裁判判了重赛。

[tosu v2 Tourney 结构](https://github.com/tosuapp/tosu/blob/master/packages/tosu/src/api/types/v2.ts) 提供 IPC、选手、队分与聊天快照，没有独立的可信 Panic / 裁判重赛决定字段。本实现不解析聊天中的命令来推断决定，也不向 osu! 房间发送命令。

## 自动检测与人工处置

- 正常、连续且完整的 Playing → Ranking 继续自动展示结算，并按稳定最终队分计胜。
- 正在进行的本局突然离开 Playing、换图、已观察到的选手窗口缺失，或 tosu 断线 / stale / 无效数据，进入持久化的“异常待核对”。窗口缺失只能说明观战资料有变化，不能自动确认是选手掉线。
- 控制台“本图异常处理”允许标记实际原因、核对恢复继续、裁判确认重赛；异常局人工计胜按明确胜方操作自动生成核对记录，补充说明可选。恢复到 Ranking 的第一帧不补记自动胜利。
- 异常状态和播出画面独立；挂起保留当前画面，可另行选择技术暂停。普通手动切画面或结束暂停不会清除异常。
- 重赛保留谱面、Pick 方、EX 与剩余次数，旧尝试不贡献赢图；若原 Ranking 已取出下一队动作，重赛会归还该动作到队列。裁判重赛入口会在同一个可撤销操作中撤回本图已有计胜，再准备新的尝试；若曾直接校正系列比分导致减分越界，会提示先核对系列分。
- 控制台与所有输出继续通过同一服务器快照 / SSE 同步；异常持久化到本机会话，可在操作记录中追溯。

## 模拟验收边界

模拟面板分别提供 Idle / abort、移除一路观战窗口、Panic 观战重建和 tosu WebSocket 断开。Panic 使用人工指定的初始化与窗口恢复序列，只用于验证信号中断时不误计胜、恢复时保留原 run；不是对真实 Panic IPC 数值顺序的声明。

需要实机录制：开打前取消、加载卡住后 abort、开打后 abort、玩家掉线但其他人继续、裁判确认重赛、Panic 后回到 Playing / Ranking、tosu 自身重连，以及实际客户端未清空旧分数的表现。当前保守挂起不能替代这些实测。

## 志愿直播员入口更新

本场设置无需保存，字段修改自动同步。顶部“处理异常”随时可找，展开后直接选择“有人卡住，先等一下”；等待只挂起 / 撤回本图，不宣布掉线或重赛。观战恢复沿用同一开打，只有“裁判已要求重赛本图”建立新尝试。完整手动调整包含本图、BP、Ban、先手、EX、逐局与系列比分。自动计胜后分数再变会撤回本图自动贡献并待核对；人工决定优先。证据见 [本轮验收](../verification/volunteer-console/README.md)。

## 自动接回更新（2026-10-29）

异常挂起只保留在本图 `incident`，不附加全局锁。继续原局、裁判重赛、人工赛果确认各自完成接回，无需再点恢复自动化。处理时以已有新鲜匹配快照重建观察位置，不恢复旧 endRun；当前无有效数据则自动等待基线。人工修正谱面／Pick 方直接生效并重建观察位置，不附加暂停或二次核对。明确暂停是独立的人为意图，异常核对不擅自解除它们。见 [本轮验收](../verification/automation-lifecycle/README.md)。
