## 2. Mappool 使用现有 MP5 与按需读取的历史完整图池

用户提供的 MP5 图池已经是完整的小图池，不是缺少谱面的展示样本。OCLR 的只读 API 也能提供历史完整图池，其他规模的真实验证资料有现成来源。

- 当前 MP5 的排版反馈直接基于这套实际完整图池、真实标题与实际状态检查。
- 需要验证其他规模或分组布局时，按需从 oclr.org 的只读 API 读取明确赛季的完整历史图池，不必虚构条目，也不要求用户再提供一套图池。
- 历史资料标明赛季和历史验证用途，不回填当前赛事的缺失数据，不把旧赛果当作当前播出结果。
- 只读取本次验证需要的图池；可复用已取得的资料，不默认拉取全部赛季或遍历所有图池。
- 调整重点是现有卡片的信息层级、间距、标题可读性和状态辨识；一次围绕一个具体问题处理。
- 保留外框表示 Pick 方、胜方角标表示单图胜方的语义，避免混淆。

现有数据入口参考：`src/oclr.js`、`server/session/data.js`。

2026-11-01 第一轮局部调整：完整 MP5 从四列改为三列，保持八行，为长标题增加宽度；两版同步，Pick 外框／胜方角标保留。见 [图池可读性验证](../verification/mappool-readable/README.md)。

## 3. BP 是局内实时进行的

取消「提前展示下一张要打什么」的改进建议。

- 不预排后续谱面，不根据轮换、胜负或图池剩余情况猜下一张。
- 只展示已经确认的当前 Ban／Pick 或当前正在比赛的谱面。
- 既有 BP 行动顺序辅助不等于提前确定谱面；不以此增加“下一张谱面”的预测展示。

## 4. 操作提示保持简洁

可以增加必要提示，但尽量减少界面复杂度。

- 优先融入现有状态区域，用一句话说明当前状态与下一步。
- 复用已有操作入口，不增加独立面板、重复按钮或额外确认弹窗。
- 设置继续修改即生效，不增加保存／应用步骤。
- 普通直播员的提示使用现场语言，技术原因保留在既有维护详情中。

2026-11-01 本地实现：原有状态区统一显示当前进度与下一步，异常和待核对结算优先；普通操作页移除原始观察器说明与重复状态文案，技术详情保留。两版验证通过，3011 自定义服务已加载；主版未启动服务，见 [操作提示简化验证](../verification/operator-hints/README.md)。

## 5. 按改动规模控制验证与 token 消耗

用户认可视觉验收，但担心反复截图、读取上下文和全面回归带来的 token 消耗。验证应与本次风险相称。

| 改动 | 默认验证范围 |
| --- | --- |
| 文案、尺寸、局部样式 | 检查受影响画面，必要时补一组长文本／拥挤状态预览 |
| TB 或其他流程逻辑 | 检查相关状态转换与必要异常边界，运行受影响的回归 |
| 公共布局、动效或捕获区相关改动 | 针对性检查布局、减少动态效果和捕获安全 |

- 已有且仍适用的截图、检查结果与上下文直接复用，不反复全文读取或重新生成。
- 不默认每次改动都运行全套截图、全部场景组合和完整回归。
- 验证优先使用隔离实例和合成会话，不干扰现场比赛。
- 发现新失败或涉及更大范围的公共逻辑时，再说明原因并扩大检查；不承诺未经测量的固定 token 花费。
- 合成浏览器检查与真实 tosu／osu!tourney／OBS 验收分开报告。
