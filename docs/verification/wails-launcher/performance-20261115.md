# Wails 与原 Win32 启动器初测

日期：2026-11-15。Windows 11 专业工作站版 10.0.26300，AMD Ryzen 9 7950X，Go 1.26.5。原版来源为 `d6f9df4`，两版均使用相同 Node 22.23.4、服务代码与网页资源。

## 大小

| 项目 | Go Win32 | Wails | 增量 |
| --- | ---: | ---: | ---: |
| OCLR.exe | 7,020,032 B / 6.69 MiB | 11,605,504 B / 11.07 MiB | 4.37 MiB / 65.3% |
| 同内容 ZIP | 37,048,548 B / 35.33 MiB | 38,752,271 B / 36.96 MiB | 1.62 MiB / 4.6% |

ZIP 对照只替换 exe，其余 Node、网页、说明与许可证相同；对照 ZIP 仅用于体积测量，不是发布包，其 manifest 未重新生成。文档或后续小改动会影响数十至数千字节。当前最终包大小另以实际产物为准。系统 WebView2 Runtime 不包含在 ZIP 内，不能把这份大小当作全新 Windows 的总安装占用。

## 启动时间

完整 GUI 启动，两版交替各 7 次，以下为中位数；首次空白配置目录的单次结果单独保留，不计入中位数。不是重启 Windows／清空磁盘缓存后的冷启动。

| 阶段 | Win32 | Wails（优化前） | 差距 |
| --- | ---: | ---: | ---: |
| 本机 HTTP 服务就绪 | 248 ms | 404 ms | +156 ms |
| 首次界面标记 | 100 ms | 377 ms | +277 ms |
| 界面显示服务可用 | 267 ms | 1,353 ms | +1,086 ms |

服务时间由测试程序从创建子进程到 `/api/health` ready 采样。Win32 界面标记在 `UpdateWindow` 后写入日志；Wails 在 Vue 更新并经过两次 animation frame 后回传标记。它们是合成测量点，不是 Windows 合成器的精确像素呈现时间。

两版的控制台浏览器加载均不计入截止时间。第一轮 Win32 在 ready 标记后仍打开控制台，Wails 则关闭自动打开，浏览器后续活动可能影响机器负载；因此这些数值作为初测，不宣称严格受控的性能基准。修正测试脚本后的重复测量尚未运行。

Wails 优化前在启动时也使用 1 秒轮询，导致服务已就绪后，按钮可能继续等待接近一秒。现已改为**启动期间每 100 ms 更新，正常运行后每 1 秒更新**。原初测 Wails 服务就绪范围 377–437 ms，界面可用范围 1,338–1,368 ms，说明主要额外等待来自状态更新周期；调整后的界面可用耗时尚未重新实测，不用推算值冒充结果。

用户按 Esc 停止桌面操作后，已停止 GUI 测量。原始去除私人路径的数据见 [performance.json](performance.json)。

## 评估

Wails 有约 4.4 MiB 的 exe 代价，压缩包增量约 1.6 MiB；本机服务启动初测多约 0.16 秒，主要收益仍是 Vue 界面维护与布局能力。原 Win32 在体积与启动速度上更有优势。首次 WebView2 安装、旧电脑、杀毒扫描以及真正冷启动仍需单独验收。
