# FM EZ 计分补偿（Issue #29）

日期：2026-11-09（America/New_York）。按用户最终确认，仅 FM 使用 EZ 额外 1.5 倍；NM 不在本需求范围内。

## 计分口径

客户端已经计入 EZ 原生 0.5 倍。直播项目将该选手的客户端分数 P 乘 1.5 后计入队分，不再乘 0.5。每名选手独立四舍五入（0.5 向上），再求队伍总和。例如原分 800,000 → 客户端 400,000 → 比赛贡献 600,000。

按实际选手 Mods 判断 EZ，支持 NFEZ、HDEZ、EZHD 等组合。图池分组来自与当前房间谱面匹配的本局条目，或图池中唯一匹配的条目；不根据 Mods 反推图池分组。NM／HD／HR／DT／TB 以及自定义版 CA 不增加本次 FM 倍率。

FM 逐人原始分数必须完整且与该侧原始队分一致，Mods 必须有效。不能计算的一侧显示未知，自动计胜等待有效数据；不会使用未经补偿的 FM 原始分数代替。图池分类缺失或有歧义时，为保留中途加入显示，继续展示客户端原始队分，并在控制台队分旁说明尚未应用 EZ 加成；不会猜成 FM。

## 实现

- `server/session/scoring.js` 唯一负责计算；`store.snapshot()` 发布 `tourney.competitionScore`，原始 `totalScore` 和逐人 `score` 不变。每次从原始输入重算，不累积倍率。
- Playing、控制台、顶栏与分差、Ranking 保留分数均消费同一份服务端比赛队分。自动结束和自动计胜也使用该计算结果。
- 房间来源一致性／观战恢复仍比较原始队分与原始逐人分数，不把合法补偿视为数据冲突。
- Ranking 分数候选同时记录原始分数和 Mods；任何有效输入变化都重新等待稳定。自动计胜后原始总分或有效比赛总分变化沿用原有撤回／人工核对流程。隐藏清零不会把合法加成撤回。
- FM 记录的 `scoreCalculation` 保存原始队分、逐人 Mods、原始／补偿分及规则版本，便于复核；明确重赛不继承上一尝试的计算证据。
- 旧保存成绩保持原值，不自动重算历史赛果。main 和 `test/custom-match` 分别沿用各自的热手、BP、Pick 展示时长和比赛状态逻辑。
