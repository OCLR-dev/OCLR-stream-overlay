# 单实例服务与原会话更新

日期：2026-10-29（America/New_York）。当前只保留一套 OCLR 实例：控制台 `http://127.0.0.1:3007/control`，独立输出 `/overlay`。3008、3009、3010 及其模拟 WebSocket 端口均已关闭。

## 原因与修复

用户在 3007 页面点击“清除标记”时收到“未知会话命令”。该页面读取了新的构建资源，但旧 Node 进程仍使用早前加载的命令处理器，不认识 `map-mark`。上一轮另起 3010 只验证了新版，没有更新用户实际正在用的 3007，造成前后端不匹配。

本次先备份四套实例的完整持久化会话和模拟房间，再优雅关闭四个已确认属于本项目的进程；新版在原 3007 / 24053 恢复同一份会话文件与房间，未重新生成比赛、未覆盖其他项目服务。

新增 `server/runtime.js`，正式启动入口与模拟器共用一个按项目路径确定的本机启动占位。它由操作系统随进程退出释放，没有过期 PID 文件。重复启动会拒绝新实例并给出现有控制台地址；开发测试使用显式的零端口隔离实例，不占用日常运行入口。该占位和模拟 WebSocket 都属于同一 Node 进程，并非额外一套控制台。

模拟器增加现有会话和房间的恢复能力，恢复发生在 HTTP / 数据订阅启动前，避免先广播一份新比赛。明确指定的会话文件不存在时拒绝启动，不静默创建空比赛。

客户端若遇到旧服务的“未知会话命令”，现在会说明“本机服务尚未更新，请重启服务后刷新页面。比赛记录会保留。”，不再让直播员误以为需要修正比分或操作顺序。
