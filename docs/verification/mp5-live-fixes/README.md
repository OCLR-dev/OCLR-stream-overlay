# MP5 Windows R5 本地修复与回放验证

日期：2026-11-07。现场基线为 `test/custom-match` / `0033bd8`（R5），通用修复同时核对 `main` / `5788822`。修复验证使用本地隔离会话与端口；未打包、部署或重启日常/Windows 服务。

## 修复与操作口径

1. **旧会话的自动 BP 接续**（自定义版）：没有 BP 规则时，控制台常驻显示规则选择入口，说明当前只跟随明确下一动作。明确选择“双方各一次 Ban → 自动交替 Pick”后，可以从开场、已有 Ban、准备中/进行中 Pick 或已结束局接续。保留 Ban、当前局、run、赛果、比分、画面和历史；只建立后续动作，重复选择不重置游标。中途加入时，不补造未知开场 Ban，也不要求补填 Roll。第二轮 Ban 已存在、暂停或异常待处理时拒绝冲突接续。模板仍只用于新建比赛，不覆盖旧 `session.json`；未知比赛不静默套用 MP5 规则。
2. **CA 元数据与参数**（自定义版）：用户在本轮明确“CA 和 FM 相同处理”。图池请求同一谱面的真实难度名和 NM 基准计算，提示中写明基准口径；Playing 使用有效选手实际参数范围。保留 CA 分类，不把 NM 基准冒充实际混合模组参数。基础元数据读取不再因计算模组条件而整体跳过。
3. **Red Pick → Blue Pick**（自定义版）：与第 1 条同源。采用明确规则后，正常释放本局 BP 即建立 Blue Pick，后续稳定房间换图自动应用；自动记胜与后续动作分别校验。没有规则的原会话仍保持未知，不猜后续队伍。
4. **Pick 展示时长**：自定义版按用户后续明确要求，从 Pick/准备生效起总计 **7 秒**，包含确认动画；替代初轮暂定的 5 秒。真实开打优先立即显示 Playing；替换重新计时，暂停/撤销/断连/人工切画面等取消，刷新和重连不重新播放。main 已有 5 秒和同图首次推送后的计时处理，本轮保留其现有行为。
5. **FM1 等待、记分、重赛与 Star**（通用）：系列校正分保留既有独立语义，控制台在改分入口明确“重赛不会自动撤回”；裁判判本图胜方使用已有“记本图胜”，重赛只撤回该图贡献，保留其他系列校正。新重赛准备记录清除旧尝试的自动结果保护标志，实际开打仍建立独立 run。大星数块改读 FM 实测范围，与参数行一致；范围使用较小字号，未移动捕获区域。缺失/错图/断连不从主控 NM、其他图或旧 run 补值。

main 仅同步第 5 条的通用显示、提示和重赛清理；没有引入 CA、自定义预设或 MP5 单轮 Ban 规则。main 原有 OCLR BP、自动 Winner、Ban 槽编辑、暂停与 Pick 计时行为保留。

## 五条问题的分支归属

| 问题 | 本次原因归属 | 修改范围 |
| --- | --- | --- |
| 1. Roll 后首 Ban 无队列 | 自定义测试版的旧会话缺 BP 预设、模板未迁移 | 测试版增加明确规则选择与接续，不把 MP5 顺序写入 main |
| 2. CA 难度名/Star | 测试版特有 CA 分类映射 | 仅测试版；main 没有 CA 分类 |
| 3. Red Pick 后无 Blue Pick | 与第 1 条同源的自定义队列缺失 | 仅测试版规则接续；不是两版自动计胜共同故障 |

## 根因与已确认事实

- 现场旧会话 `bpRule=''`、无 `bpPreset`、`bpFlow.mode=manual`、后续队列为空。自动 BP 开启不代表已选规则。蓝 FM2 Ban 和红 HD1 Pick 曾由 `room-map` 执行，不能归因为全部换图失效。
- HD1 已记录红 `1745678`、蓝 `1208841` 且 `bpReleased=true`；原会话没有可继续的 Blue 动作。
- CA 原接口已有真实难度名，但前端因 CA→null 直接跳过元数据。新的真实接口检查得到 CA1 `Lunatic` / NM 基准 `5.58`，CA2 `Kotori's EXTREME` / NM 基准 `5.44`；计算库版本及模组口径与现场 tosu 数值分开。
- FM1 的主控总星数 `5.53` 一直存在；本轮分析 8,520 条 FM1 原包（比此前 7,832 条区间更长），发现 2,029 条 Playing 和 526 条 Ranking 的有效选手星数范围为 `5.53–5.93`，而共同单值为 null。旧大星数块只读共同单值，参数行本已读范围。同源双页面对照复现旧版“—”、修复版“5.53–5.93”。加载期也存在真实 `5.53–5.88` 范围；另有 2 帧选手参数确实缺失，应继续未知。这证明可复现的前端断点；用户当时主观看到消失的具体时刻/区域仍无原始屏幕录像，不能反推每一帧界面。
- 现场蓝队那一分来自 `set-series`，不是本轮胜方记录。重赛保留它是既有系列校正语义。回放重现保留 `3:1`，再按现场后续明确改分回 `3:0`；没有在修复中替现场清除校正。

- 新增规则有/无、旧会话优先恢复、已有动作无损接续、重复选择、无 Roll 中途加入、旧待处理换图不重放等回归。保留现有暂停/撤销/断连/准备替换/TB/手动规则回归。

- **FM1 重赛段原速回放**：原帧 15862–17911，共 **2,050 帧**，原跨度 **313,872.641ms**，同一真实链路，最大调度迟到 **9.943ms**。使用保存的 v157 公共会话，隔离补空 undo/commandIds；按历史时间发送重赛、切画面和系列改分。新 run 记录 `1958881:1714034`，系列 `4:0`，原尝试作废，没有重复贡献。
- **主动旧 Ranking 对抗**：在另一份隔离会话重赛准备后注入未修改的旧原帧 11753–11757，按该段原间隔发送；保持 prepared、runId=null、无赛果、系列 `3:1`。再按原间隔发送真实 Ready/Playing 片段，建立独立新 run，校正分仍保留。这是有意插入旧消息的对抗序列，不伪装成现场自然顺序。

## 边界与未验收项

- 原采集共 21,396 帧/14 分片、1,511 份约每 2 秒的 HTTP 快照。启动前 Warm-up/Roll/首 Ban 原包缺失；末尾约 68.552 秒无新消息的原因仍未知。未覆盖、重写或补造证据。
- 本轮证明本地复现与修复链路，不代表 Windows 原生 osu!tourney、tosu、游戏捕获和 OBS 已重新验收。未重打 Windows 包，未连接/修改 Windows 或日常比赛服务，未改真实比赛记录。
- `early-ipc`、`coherent-stale` 的完整旧分数快照提前计胜风险仍保留。旧 Ranking 在新准备阶段不计胜，不能证明任意完整陈旧 Ranking 在新 Playing 后都能识别；本轮未改变自动判定算法，也没有重新裁定现场赛果。
- 用户后续已确认自定义测试分支采用 7 秒；main 保留现有 5 秒。上面的约 5007ms 页面测量保留为初轮 5 秒实现的历史验证，不作为 7 秒实测。
