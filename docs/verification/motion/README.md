## 实现

| 位置 | 表现与边界 |
| --- | --- |
| 七个常驻场景 | 200ms opacity 交叉淡化；直接响应最新 scene，没有 out-in 等待、历史动画队列或业务延迟。退出场景立即 inert / aria-hidden，视觉退出结束后隐藏。 |
| Roll | 真实点数、胜方、先 Pick / 先 Ban 变化时，当前可见字段单次 240ms 透明度强调；不随机滚点。 |
| 图池 | Ban / Pick / 已打标记及队属实际变化时强调一次，清除或撤销也会反映；不重建谱面列表。 |
| 系列赢图 | 菱形行与系列数字实际变化时强调一次，包含撤回和纠错；不对高频实时总分添加动效。共享输出的分差带直接更新。 |
| Winner | 胜方文案额外 300ms / 6px 入场；已展示时修正胜方使用 300ms / 4px 强调。没有遮挡信息的装饰层。 |
| 控制台 | 按钮保留 150ms 颜色反馈；面板、比分与反馈不降低透明度。请求期间不批量变暗，真正不可用的按钮仍保持禁用外观。成功、错误、撤销在固定高度反馈区域呈现，长文在区域内滚动。字段同步提示预留行高。 |

`ui/motion.ts` 的原生 Web Animations 指令只比较小型语义值；同一元素的新强调先取消旧动画。它不挂载到游戏源、实时分数或捕获祖先上。场景淡化使用 CSS，源窗口的 transform / filter 始终为 none，Playing 与结算继续使用常驻、按选手槽位稳定 key 的原组件。没有增加依赖或直播员设置。

`ui/session.ts` 的 presentationEpoch 只用于浏览器呈现：首次有效快照、重连和新会话建立静默基线，不补播过去的操作。重复快照、相同值和隐藏场景不重复强调。减少动态偏好下 CSS 过渡、环境动画与新增强调全部关闭；偏好在强调中启用时也立即取消原生动画。比赛状态不依赖动画、动画结束回调或延时。

服务端计胜、记录、纠错、异常、重赛、等待核对及自动观察时序本轮均未改动；既有完整旧快照风险仍存在，未通过延长等待规避。OBS 继续使用同一个 `/overlay`。

## 后续修正：比分自动同步与控制台闪烁（2026-10-29）

按用户截图反馈，移除“应用正确系列比分”按钮。两侧分别加入现有自动设置队列：输入停顿 450ms 或失焦后提交；保留各自未提交草稿，另一队使用当时最新共享比分，版本冲突重试时重新读取另一侧，避免覆盖并发记分。相同值不新增校正记录。空白、非整数及越界值不发送，真实零正常保存；成功后输入继续随 SSE 和撤销更新。

检查发现请求期间所有受 busy 控制的按钮会从 opacity=1 短暂变为 .48，加上整个反馈区域 / 左面板的透明度强调，会造成操作时的闪烁。已取消控制台的这些透明度强调及每次请求替换反馈文字的行为，区分“正在请求”与“业务上不可用”：前者保留锁定但不变暗，后者继续保持禁用外观；hover 状态也不因短请求突然消失。播出端动效保留。

本机隔离模拟浏览器验证通过：无确认按钮；输入框保持焦点时蓝队 3→4 自动同步到独立输出；红队空白不变零，编辑蓝队不覆盖红队空白草稿；越界输入不应用；真实零正常同步，撤销恢复输入值。25 次样式采样中捕获 2 次 busy：六个场景按钮仍 disabled，但 opacity 全部为 1，反馈和左面板也为 1；真正不可用的 EX 加次按钮仍为 .48。

类型检查、构建、84 项回归测试及 diff 检查通过。未新增依赖，未改系统偏好，未提交或推送。证据：[无需确认的比分界面](series-autosync.jpg)、[自动同步与请求中样式量测](series-autosync-checks.json)。本节覆盖前文旧截图和旧验收步骤中的按钮确认与控制台面板动效；播出端及真实 OBS 验收边界不变。
