## 本轮行为

左侧管理面板由当前播出画面决定，真实比赛记录独立保留：

| 播出画面 | 左侧管理内容 |
| --- | --- |
| 等待 | 到场、就绪 |
| Roll / 先手 | 双方真实点数、Roll 胜方、先 Pick、先 Ban；修改自动同步 |
| 图池 / BP | 明确队伍的四个 Ban / Pick 按钮、可直接点击的谱面、Ban 清除修正 |
| Playing / 单图结算 | 系列比分校正、人工记胜、撤回和胜方修正、必要时手动标记开打 |
| Winner | 全场胜方确认、存档与下一场 |
| 暂停 | 暂停类型、返回原画面 |

- 切回图池不要求先计胜。前一局尚未记录时，可以先 Ban 或准备下一张 Pick；前一局继续保存在 Playing 的待记录列表中。补记上一局不覆盖新选图。
- 已准备的本图可直接替换谱面或 Pick 方，保留同一轮、EX、系列比分和后续动作；Ban 修正不消耗下一轮 Pick。完整 BP 顺序仍只接受已核实配置。
- Roll 修改只改点数和先手，保留当前开打、BP、EX 和比分，也保留自动结算观察的连续性。未知点数与真实零值分别保存。
- Playing 人工记胜只记录选中的局，不强制切回图池；达到目标后也需单独展示 Winner。重复计胜被拒绝，正常可信结算仍自动计胜。
- 新 Pick 与实时游戏谱面不一致时，Playing 队分显示未知，不挪用上一张图的分数。
- 一键画面栏、暂停 / 恢复、撤销、异常入口和双方 EX 次数保持常驻。本场设置自动同步与页面内选择器定位修复继续保留。

## 未验证边界

本轮没有进行真实 osu!tourney / tosu / OBS 联调，也没有邀请首次使用的志愿者实测。浏览器结果仅证明本机模拟数据下的操作和同步行为。

此前 17 种结算时序模拟的 2 种完整旧快照提前计胜风险仍未消除，不能把分数稳定或一致当作所有人已结束的证明，也没有通过加长固定等待时间宣称解决。有人未结束时仍可等待并撤回本图自动贡献，之后核对、人工记胜或按裁判要求重赛。原始基线及后续变化分别见[结算时序报告](../result-timing/README.md)和[整体改造验收](../volunteer-console/README.md)。游戏捕获、实际 EX 阵容及 OBS 叠放仍需真实直播机验证。
