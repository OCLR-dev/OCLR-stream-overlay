# 自动化、直接编辑与恢复验收

日期：2026-10-29（America/New_York）。仅模拟流程及本机浏览器／OBS 显示验证通过，未完成真实 osu!tourney／tosu 直播验证。没有提交或推送。

## 根因与最终行为

原实现的默认开关为关闭；保存未核实房间配置又会关闭开关。切画面、准备／调整本图、部分资料导入写入全局 `locked`；大量人工命令清空整个观察器；开打、结算身份与自动计胜依赖 `auto.scenes`。这些行为会使正常流程在局部修改后长期停住，或丢失连续结算。

最终实现：

- BP、画面跟随、计胜默认开启且独立。缺少绑定、错误房间、断线或过期是执行条件不足，保持设置，条件恢复后自动建立基线并等新事件。不猜客户端、左右队名、BP 顺序或赛果。
- 没有全局人工模式，没有“持续人工接管／恢复自动跟随”按钮，也不再保存 `locked`。修改当前画面和相关内容直接生效，数据跟随继续。
- `sceneOverride` 仅覆盖画面。下一次通过校验、稳定防抖且适用于当前局／动作的换图、开打或结算事件接回；重复 Playing、旧 Ranking、分数刷新不抢回画面，没有超时抢回。关闭自动选画面则保持人工显示，BP／计胜仍独立工作。
- `paused` 是明确暂停：即使另切显示画面仍不自动推进。结束暂停本身重建安全基线；不补记暂停期间错过的结束事件，已结束的局由直播员核对后直接记胜。
- `incident` 保留现有异常分类与裁判职责。观战／连接在已开打局中断时核对，继续原局保留 run，裁判重赛建立关联新尝试，人工赛果保护旧局。每种处理动作本身接回，不需要第二次开启。
- 人工更正谱面／Pick 方不额外产生暂停或异常。真正的来源中断、房间绑定在进行中改变等仍要求本局核对，不能把其他房间复用为本次 run。
- 人工操作按实际改变的局次、绑定、暂停和异常状态处理连续性；Roll、标记、EX、普通设置、画面及补记旧局不清空无关观察。当前动作改变会取消对应待处理换图，不把旧事件转给新动作。
- 需要重建基线时，若已有新鲜且匹配的快照，直接将其消费为观察位置，但不恢复 Playing 边沿或 endRun 结算资格。这样人工核对后立即到来的新换图不会被吞成首次基线；若没有快照则等首帧，不补旧 Ranking。
- 撤回和修改结果保留人工优先；校正系列分时已发生的结算受保护，后续真正的新局仍自动累计。Playing 中校正系列分不免除该局后来队分变化的核对保护。Winner 始终由直播员明确展示。

`automationVersion=3` 同时升级会话和撤销保存域。能从撤销记录追溯到切画面／准备图／资料修正的旧隐式锁迁移为画面覆盖；旧明确或来源不明的持续锁迁移为暂停，保留原显示，可用结束暂停一次恢复。保留已明确关闭的 BP／画面设置及新版计胜开关。未配置旧默认值升级为开启意图。

## 编辑入口核对

| 编辑 | 生效方式 |
| --- | --- |
| 标题、阶段、队伍、名单、图池、人数、比例、房间绑定和跟随设置 | 下拉立即，文字／数值停顿 450ms 或失焦同步 |
| Roll 点数和先手，包括更多调整中的重复入口 | 同上，无保存按钮 |
| 系列比分 | 双方独立同步，另一侧取最新值，空白和越界不写入 |
| EX 开启方和剩余次数，包括更多调整 | 下拉立即；双方次数分别自动同步，不覆盖另一侧新值 |
| 当前谱面／Pick 方 | 修改立即生效，保留局次与 run；不附加全局停用或再次确认 |
| 准备本图 | 谱面与队伍选全后立即准备；真实开打仍依赖有效 Playing 或明确人工开打动作 |
| 当前 BP 动作与后续顺序 | 明确选全队伍、动作与 Ban 槽后同步，不设默认队伍／动作／槽；来源说明可选 |
| 图池标记、撤回和胜方修正 | 点击对应动作直接应用，保留撤销 |
| 人工记胜 | 直接点击“记本图／上一局 某队 胜”，没有胜方草稿与第二次保存 |

“选择某局”“选择要标记的图”只是定位操作目标，不写结果。初始化、重赛、作废、暂停和展示 Winner 是明确动作；初始化仍有清空范围说明及存档／撤销。可选补充说明随对应动作记录，不构成保存门槛。

本图自动同步携带 `ifCurrentRoundId`；如果同步／版本冲突重试时已切局，拒绝写入新局并提示重新修改。输入草稿按字段保护，切换比赛清除旧草稿、待发设置与反馈。

## 结算时序限制

`sim:timing` 对抗探测仍为 **17 种中 15 种符合预期，2 种风险**，命令按设计退出码 1。[本次报告](result-timing.json)。完整且一致的旧快照在 IPC 提前到 Ranking 时仍可能提前计胜；一致性校验和 250ms 稳定不能证明所有真实选手已结束。本次没有延长任意超时来宣称解决，也没有把模拟通过写成真实 tosu 时序可靠。真实 osu!tourney／tosu 的 abort、Panic、旧分数清理与最后一路结束生产时序仍待实机证据。
