# 实时比分连续计数（Issue #17）

2026-11-07 用户澄清：需要分数数值在两次上报之间持续变化、平滑追上目标值，不是字形缩放或弹跳。

## 实现

- 仅 Playing 的双方实时队分（含 Warm-up）使用 requestAnimationFrame 插值；每次从当前显示数值向最新目标作 120ms 线性过渡，新上报直接接续，不排队。
- 显示值取整，保留各分支原有分组格式；不改变字形大小、捕获区域或比分布局。
- 中间数值仅存在于 ScoreCounter 组件，绝不写回共享会话，不参与计胜、分差计算或赛果判断。视觉数值可短暂落后最新目标，结算立即贴准。
- 首次加载、重连、新局/run、错图切换、未知、归零、向下校正和 Ranking 直接显示准确值，不播放追分。相同目标不延长计时。
- 减少动态效果开启时直接更新；后台页不请求动画帧，切回时建立最新基线。组件卸载清理帧与监听。
- 保留 main 的 #14 UI 改动和 5 秒 Pick；测试版仍保留 CA、自定义规则和 7 秒 Pick。

## 验证

- main 34 项、测试版 33 项针对性回归通过，覆盖逐帧中间值、快速接续、重复快照、结算贴准、归零/纠错/未知、位数增长和分组。两版类型检查、隔离构建通过。
- 在实际 WebSocket → 共享会话 → SSE → Vue 的隔离预览中，读到显示值 761,1802 / 764,7409 正在追赶目标 761,7778 / 765,7222；旧逐位弹跳节点数量为 0。
- 注入 Ranking 后，画面准确显示 195,8881 / 171,4034；归零帧准确显示 0 / 0。捕获表面仍透明、尺寸与原预览相同，未添加数据连接。
- 单元测试证明 120ms 内包含多个递增中间值；浏览器观察证明呈现中间值，不代表对 osu! 原生算法或 Windows/OBS 效果已做等同验收。
- 用户已查看连续计数预览，本次作为两分支通用更新提交；Issue #17 随提交状态更新。减少动态效果与页面可见性保护已实现；未切换用户系统偏好来验证。
