# 仅模拟 tosu，赛事资料保持真实只读

日期：2026-10-29（America/New_York）。用户明确修正了模拟范围：tosu 是 osu! 游戏数据源，OCLR 是独立的赛事资料源。普通测试应使用真实历史对阵和图池，只模拟游戏信号。

## 修复

- 原 `startSimulation` 为整个 OCLR 代理注入 `SIMULATION_OFFLINE`，不论赛季都返回读取失败；这不是 S10 不支持。现在普通模式加载现有服务端配置，经原 HTTPS、GET 白名单代理读取真实 API。保留 bearer，401／403 明确阻断，不退回匿名，Key 不进入页面或测试样本。
- 完全离线的合成对阵、图池和固定 BP 序列仅通过 `--offline-oclr` 启用。现有回归／时序脚本都显式使用该模式，不读取本机凭证，不访问真实 API。随机端口测试还必须指定会话副本或离线模式，不能隐式打开当前持久化比赛。
- 普通模拟默认打开 `.local/session.json`，与正式入口共享同一比赛存储；没有初始模拟对阵。显式指定的旧文件仍支持恢复，文件缺失时拒绝新建替代比赛。
- 模拟器的谱面列表与标题取自本场图池，实时更新；可手填谱面 ID。房间左右队名由测试人员明确填写，不推定历史队伍就是房间队伍。
- 普通信号重置保留比赛、图池、BP、比分、历史和房间队名。自动演练只发送当前池内谱面的 Playing → Ranking，不重置比赛或编排 BP。开打中主动重置信号仍可能触发已有本局异常待核对，这不表示裁判重赛。
- 选手、实时分数、IPC、谱面参数与故障仍明确为模拟。会话和界面分别标识 `tosu: simulated`／`oclr: remote-read-only`，不会把游戏合成数据说成真实比赛结果。
- 真实 S10 快照约 88KB，超过流高水位。旧 SSE 把 `write() === false` 当成断线，导致目录加载后反复重连；现在等待 `drain`，慢读者只保留最新快照，心跳也尊重背压。刷新时输入框显示当前已加载目录的赛季。

真实网站目录和合成游戏信号已分别验证；没有连接真实 osu! 房间，没有推流、录制或改动 OBS。真实 tosu／osu!tourney 的结束生产时序仍未验证，原完整旧快照提前计胜风险没有被本次来源分离解决。

## 当前实例与数据保留

控制台与输出仍为 `http://127.0.0.1:3007/control`、`/overlay`，tosu 模拟器仍为 `http://127.0.0.1:24053/` 与 `/websocket/v2`。只有同一 Node 进程监听这些地址，没有另留日常端口。

更新前已备份当前比赛、完整模拟房间和临时会话的全部存档；在旧服务正常退出后，将比赛原字节复制到此前不存在的 `.local/session.json`，并无覆盖迁入 1 份旧存档。原临时存储保持完整，备份位于被忽略的 `.local/tosu-only-simulation-2026-10-29/`。更新前后比赛快照逐字段一致；读取 S10 不改现有比赛。

后续维护启动同一端口：

```sh
npm run build
npm run sim -- --app-port 3007 --ws-port 24053
```

需恢复某份游戏房间状态时附加 `--room-file`；比赛默认从持久存储恢复。与比赛重置不同，重置 tosu 信号不会清空已选历史场次。

Key 仅保留现有服务端凭证引用。更新凭证后需有序重启加载，Origin 匹配服务端 `OCLR_API_ORIGIN`；不把 Key 填入控制台或模拟器。开发者 Key 的失效机制来自网站合同，不因模拟模式绕过。
