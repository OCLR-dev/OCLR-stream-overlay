# OBS 弹幕来源复用

2026-11-14，修复独立 Showcase 预览与正式服务连接同一 OBS 场景集合时，将已有弹幕源误报为重名冲突的问题。

## 行为

在当前场景集合的输入列表中查找浏览器源及相同弹幕地址，找到后保存其来源标识并添加到目标场景；自定义样式保留。已改名或本地旧标识失效的来源也按实际地址发现。没有匹配来源时创建新的浏览器源；名称与其他输入、场景或组冲突时自动添加编号。每个场景集合分别保存关联，集合切换仍通过原控制器的操作校验中止未完成请求。

## 验证

- 主线构建通过，532 项回归及临时副本中空闲端口的 2 项便携服务测试通过。
- OBS 专项共 33 项通过，覆盖两个独立控制器共享来源、自定义样式保留、重复操作无写入、失效标识／改名、不同来源自动加编号及不同场景集合隔离。
- 本机真实 OBS：独立预览此前没有保存弹幕来源标识；应用修复后自动发现原来源，将同一来源标识挂入 Showcase，状态为 `configured`。来源总数保持 16，未新建重复来源；弹幕浏览器设置、常规／EX 两场景、当前 Program 和 Showcase 图池／Stage 文件均与操作前相同。只重启 49514 独立预览，3001 服务保持运行。脱敏结果见 [本机检查](local-obs-checks.json)。

本次验证了本机 OBS 连接及来源复用，未验证真实观众弹幕到达，也不代表 Windows osu!／tosu／回放合成验收。
