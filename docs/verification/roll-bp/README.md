## 最终流程

先 Ban、先 Pick 各自明确后，`set-roll` / `roll` 在未开始且未手动编排的比赛中立即建立 **当前动作和后续顺序**。不依赖 Roll 点数、胜方或红蓝位置推断另一项先手；两项可以同队。Roll 画面保留点数与两项独立选择，不新增保存、应用或确认按钮。可直接查看图池，或等待有效房间换图接回。

以红先 Ban、蓝先 Pick 为例：

1. 红 Ban 1 → 蓝 Ban 1。
2. 蓝 Pick 1 → 等待开打 → 本图有效结束。
3. 红 Pick 1 → 等待开打 → 本图有效结束。
4. 红 Ban 2 → 蓝 Ban 2。
5. 蓝 Pick 2 / 比赛 → 红 Pick 2 / 比赛 → 蓝 Pick 3 / 比赛 → 红 Pick 3 / 比赛，继续交替。

后续 Pick 成对按需补充，无需直播员编排。胜方不会改变轮换。每次 Ban 消耗当前动作；Pick 消耗选图动作后只建立准备局，等待真正 Playing。准备期改图只替换同一轮，保留 Pick 身份、次数、队伍与后续顺序。

有效结束与计胜分开：连续有效 Playing → Ranking 释放一次下一动作，待记录赛果仍可保留，下一图可以准备并开打。人工记胜和补记旧局不再次取队列。若自动漏掉结束，Playing 中可以点击“本图已结束，继续 BP（暂不计胜）”；存在异常时仍须按原有异常核对流程处理。

系列达到目标停止执行 BP，保留动作供比分纠错后核对，不继续消费谱面。自动顺序在 BO11 的第 10 张常规图／BO13 的第 12 张常规图结束后，或双方已到决胜比分时，等待核对赛果与裁判决定；不会把下一普通 Pick 当作 TB。图池折叠区单独准备 TB，谱面和用于本机记录的队伍须明确选择；不从 Roll 推断 TB 归属，不自动宣判进入 TB。TB 不消耗普通 Pick，禁 Ban / EX，结束后不继续普通队列。自动序列下普通图与 TB 不能通过改图互相转换。

## 恢复与兼容

- 图池“当前 / 接下来 / 已选图等待开打”读取服务端 `bpProgress`。自动化意图保持开启，没有有效房间绑定则明确等待，人工补做不伪称已操作房间。
- 队伍 Ban / Pick 和清除标记继续只调用 `map-mark`，可独立修改已打图。漏记时点击“人工完成当前真实 Ban / Pick”，与自动换图共用 `applyBp`；准备图使用“替换本次准备图”。两组按钮有文字分隔。
- “裁判已确认空 Ban”仅处理当前 Ban，保存空槽标志和 BP 历史，进入下一步；没有计时、超时处罚或猜测。可撤销。清除真实 Ban 不自动倒退进度，可手动指定补做动作。
- 持久化当前动作、队列、原始先手、Pick 次数与局次释放标志。刷新、多输出和重连不推进，恢复仅建立观察基线。待稳定换图绑定原动作／轮次；人工完成、修改动作或撤销后，旧事件不能转给新动作。
- 重赛是原 Pick 的新尝试，归还 Ranking 时已展示的下一动作；首 Pick 重赛不会提前触发第二 Ban。原尝试作废，不计新 Pick 次数。后续 Ban 已执行时，迟到重赛须先撤销后续 BP，避免静默删除真实记录。取消尚未开打的启动不创建重赛。
- 作废当前普通选图后恢复该次 Pick，重新选图，避免跳过第一轮比赛。人工调整本图 Pick 方不改变既定后续轮换。
- 加载既有会话不会重排或覆盖原动作、手动队列和进行中的 BP；缺少新字段按旧会话处理。先手修改在真正 BP 开始前可以重建尚未执行的开局，开始后冻结实际顺序，只更新 Roll 展示并提示如何纠错。赛前资料在 Roll 后加载也保留已建立动作。
- 原有“更多调整 → 当前 BP 动作”和“本场设置 → 纠错：修改后续 BP 顺序”仍可直接编辑、撤销。显式修改采用该手动 BP 队列，保留当前局与已发生记录，不再自动补充交替 Pick；房间观察、自动选画面与计胜开关保持原意图。这是 BP 队列归属，没有全局人工接管开关。
- 兼容旧会话中“前一局还标记 Playing，但已准备新一局”的历史状态：补记旧结果不会消费新局队列。新操作要求先有效结束本图，仍不要求先计胜。
