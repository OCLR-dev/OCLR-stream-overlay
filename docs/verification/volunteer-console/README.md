日期：2026-10-28（America/New_York）。本轮在既有未提交的事故处理、模拟器与时序诊断改动上继续开发，没有重置、提交或推送。

2026-10-29 更新：本文保留前一轮整体改造记录；管理面板已改为跟随所选画面，取代此前按比赛进度显示操作的方式。当前验证见 [面板职责验收](../scene-management/README.md)。

## 实际交付

- 三个页面入口：比赛中操作、开播前设置、维护详情。比赛页突出对阵、系列比分、当前图、实际进度和下一步。IPC、版本、存储与原始读数仅在维护详情或房间配置中显示。
- 本场设置全部自动同步：阶段、人数、源比例等选项立即应用；标题、队名、名单与图池文本停顿 450ms 或离开输入框后应用。房间跟随选项、已核实 BP 配置与完整资料选择同样自动同步，无保存按钮。无效草稿就近提示，保留有效状态与其他字段草稿。
- 主操作由比赛进度决定，等待 / Roll / 图池 / Playing / 单图结算 / Winner 六个画面按钮常驻，一键切换并高亮当前画面；手动重看图池 / Playing / 结算仅改画面、暂停自动跟随，保留真实比赛进度。
- 明确队名的四个 Ban / Pick 按钮与可点击谱面卡。未确认完整 BP 顺序时逐次指定动作；组织者可通过结构化表单配置后续动作，必须填写核实来源，无预置完整规则。
- 正常模式主要显示对阵、当前情况、下一步与较大的浏览器预览。六个切画面按钮、暂停 / 恢复、自动跟随开关、撤销、异常入口和手动调整入口常驻；细节 BP / 改图 / 记胜平时收起，检测到事故后自动展开，不把防御性操作变成日常步骤。无需 OBS 切场景或确认。
- 双方 EX 剩余次数常驻主界面，直接加减、立即同步并支持撤销。在比赛中调整次数保留当前 EX 开启方和同一次开打，也保留自动结算连续性；开启最后一次后可把剩余改为零。
- 现场处理使用“还没开始就卡住”“有人尚未结束”“直播画面异常”“裁判已要求重赛”。自动记录对应原因，补充说明可选。等待会撤回本图已有计胜；裁判重赛在一个可撤销操作中撤回本图、作废原尝试并准备重赛，保留其余局的贡献、Pick、BP 与 EX。
- 完整手动调整保留当前图 / Pick 方、BP 动作 / 取消动作、指定 Ban 槽修正、先手归属、EX 开启方、逐局胜方 / 撤回、绝对系列比分。当前图和先手修正不会重置整场；改图主动暂停自动跟随。
- 自动计胜增加管理器队分与逐人分数一致性校验，缺失与真实零值保持不同。自动计胜后同图 Ranking 分数再变，会撤回该局自动贡献并挂起核对。人工胜方与直接比分校正优先，不被旧帧覆盖。

- `npm run check` 与 `npm run build` 通过。
- 修复用户截图中的原生选择器弹窗错位：控制台统一使用页面内定位的组合框 / 列表框，菜单按触发框定位、靠边约束，可向上展开；方向键 / Home / End / Enter 选择、Esc 取消。桌面菜单与触发框同 x，间隔 4px；390px 窄屏实测菜单 x=49…229、y=447.844…543.844，位于 390×844 视口内。
- `npm test`：76 项通过。新增覆盖分数不一致 / 缺失 / 零值、迟到分数挂起、人工结果优先、单步等待 / 重赛及撤销、当前谱面和先手局部修正、已核实 BP 配置、比赛中逐字段设置 / 撤销、图池引用保护与设置期间自动结算连续性、比赛中 EX 次数修正与连续结算；保留既有 HTTP 同源和资源隔离、SSE、多订阅、真实本机 WebSocket 测试。

- 浏览器使用独立 3007 / 24053 模拟服务，不改变原有 3005 / 3006 服务的比赛记录。控制台、另一个控制台和独立输出均连接同一份服务端会话。
- 浏览器通过：手动 Ban / Pick；开打前取消后继续等待原图；房间 Playing 自动开始；等待最后一路时 Ranking 不加分，核对后人工记胜；模拟 Panic 后继续原局；重看图池不改变 Playing 进度；裁判重赛撤回原局并只计新尝试；胜方修正、撤销、撤回与重记；直接比分校正；阶段立即同步 BO13 / 先 7 / 双方各 7 颗菱形。
- 浏览器补充通过：并行修改标题 / 人数 / 比例 / 队名 / 名单后均同步，原 Pick 与 BP 保留；删除已选图被拒绝，修复后自动应用；比赛中改标题后同一局仍正常自动结算；自动跟随开关与 BP 核实来源刷新后保留；设置页保存按钮数量为 0。完整 OCLR 资料选择的远端交互未实测，导入的局部更新通过模型回归验证。
- Playing 与结算各 8 个窗口，逐窗位置和尺寸完全一致，原始矩形见 [geometry.json](geometry.json)。
- 桌面 1440px 与窄屏 390px 检查，量测见 [browser-final.json](browser-final.json)。窄屏正文宽度等于视口，无横向溢出；完整手动调整可直接展开并跳转，窄屏 EX 按钮可直接操作。
- 多个控制台和独立输出同步验证。曾因重复预览订阅占满浏览器同源长连接导致测试请求排队，现已让控制台 iframe 复用父页已有的 SSE 快照并校验消息来源；独立 /overlay 仍直接订阅服务端 SSE。浏览器检查预览 transport 为 parent-preview，切画面、EX 调整与撤销同步通过，运行日志无 error / warn。该优化不增加任何直播员步骤。

## 尚未验证与剩余风险

- 完整、彼此一致的旧快照冻结时，当前数据缺少可信的逐人结束 / 字段新鲜度标识，仍可能提前自动计胜。迟到变化会触发核对，但冻结期间的提前加分风险没有消除；不能靠延长固定等待时间宣称解决。直播员发现有人未结束时，可点“处理异常”→“有人卡住，先等一下”，撤回本图已有计胜并禁止自动重记。
- 一致性校验只是必要校验，不证明全部结束。命中数不足场景本轮被其个人分与管理器不一致拦截，不是实现了按命中数判定完成。
- 游戏捕获、OBS 聊天叠放、实际 EX 阵容映射、真实 osu!tourney / tosu 的时序和直播机性能尚未联调。模拟器只验证本机行为与传输链路。
- 尚未邀请真实首次使用者进行可用性测试；当前是按新手操作路径执行的开发验收，不能冒称志愿者实测通过。

用户现场反馈已落实：切画面属于高频操作，移出折叠菜单，恢复常驻的一键画面栏。技术详情仍可折叠；切画面不再需要打开二级入口。

最终交互按用户反馈收束：切画面与 EX 次数为常用操作，始终直接可见；自动流程是主界面，完整手动能力用于处理意外，操作后可恢复。
