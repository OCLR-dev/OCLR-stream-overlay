# Windows 便携版使用说明

适用：Windows 10 / 11，Intel 或 AMD 64 位（x64）。无需安装 Node.js、Git，不用输入命令。包内附带 tosu；osu!stable、OBS 需自行安装。

> 开播前在 OBS 节目画面核对捕获窗口，在混音器核对音量。下面的操作与本包对应；下载其他版本时请使用该包随附的《使用说明.txt》。

Windows 启动窗口使用 Wails + Vue，需要 Microsoft Edge WebView2 Runtime。缺少时按安装提示完成后重开；离线机器请提前安装运行时。

## 1. 获取压缩包、解压、双击启动

1. 在 [GitHub Releases](https://github.com/OCLR-dev/OCLR-stream-overlay/releases) 选择所需提交的 Pre-release，从 Assets 下载 `OCLR-Windows-x64.zip`，右键“全部解压”。可用旁边的 `.zip.sha256` 核对下载内容。
2. 双击解压后的 **OCLR.exe**，等待直播控制台在同一窗口载入。从「比赛配置」完成开播前准备，再到「比赛现场」操作。需要网页时点「在浏览器打开」。
3. 「Showcase」在顶部导航。切换页面、重新加载控制台和最小化会继续播出。重复打开程序时回到已有窗口。关窗或点「退出服务」会询问是否停止播出，确认后保存比赛并退出。

如果窗口显示「等待服务响应」，启动器会继续检查，控制台重新连接后会同步最新状态。如果服务无法启动或已停止，在控制台可重试、改端口或查看日志。「关于」可查看构建标识、项目主页、开源许可及版权信息。

## 2. 载入本场直播任务

在「比赛配置 → 本场资料」登录 OCLR 并授权本场赛季，选择自己的直播任务，核对对阵、开赛时间、图池和赛制后点击「使用所选直播任务」。任务提供的双方队伍可带队旗，实际上场名单请在「手动编辑队伍、名单与图池」中核对录入。

从桌面点「登录 OCLR」后，在系统浏览器点「前往 OCLR 授权」。授权完成后返回桌面，任务会自动显示。重启服务、更换端口后请重新授权。

启动时若看到「继续上次的比赛？」，接着播同一场选「继续上场比赛」，换场选「存档并开始新比赛」。比赛进行中接手也可直接读取房间和谱面，先播 Playing，再补需要的本场资料。

练习时可以从「从 OCLR 已发布资料选择」载入注明赛季的历史对阵和图池。例如选择 S10 的 Group A 1 与 Group Stage 1，使用本机练习比分。正式开播时请切换到本场任务。

## 3. 连接 tosu 与 osu!Tourney

启动器默认识别同一解压目录下的 `tosu/tosu.exe`，无需先选择路径。建议先打开 osu!Tourney，再在「服务」点击「打开 tosu」。未检测到 osu! 时会提示，可选择继续或先打开游戏。需要使用自己的 tosu 时，在「设置」选择程序；有效的自定义路径优先，失效时回退到包内版本，「设置」显示实际使用的路径。整包移动后会重新定位包内程序。

包内 `tosu.env` 以本机 `127.0.0.1:24050` 为默认地址，开启自动更新，关闭启动时打开 Dashboard 和游戏内 overlay。完整默认值见 [tosu.env](../tools/packaging/tosu.env)。启动器以 tosu 所在目录作为工作目录，支持 `STATIC_FOLDER_PATH=./static`，读取配置时不改写已有设置或未知字段。

`tosu/bundled-release.json` 记录 CI 打包时的版本、下载校验与来源；自动更新后的实际版本以 tosu 自身显示为准。更新 OCLR 建议解压到新目录；若需要沿用旧配置，将旧 `tosu.env` 复制到新包的 `tosu/`，不要直接覆盖正在使用的目录。

启动窗口按所选 `.exe` 的完整路径检查程序是否运行，运行时会停用「打开 tosu」以避免重复启动。端口检查会定期重读所选程序同目录下 `tosu.env` 的 `SERVER_PORT`，并显示 `127.0.0.1` 上该端口的连通状态。若文件缺失、无法读取或未提供有效端口，启动窗口会显示对应提示。游戏数据是否就绪可在直播控制台查看。

1. 在直播控制台连接 OCLR 授权赛季，等到连接成功。即使没有待播任务，仍可使用已授权的赛季。若连接中断，等恢复后再操作。
2. 在启动窗口的「设置」点「选择 osu!.exe…」，选取本机已安装并登录的 osu!stable。建议为直播使用独立的 osu!stable 安装目录。[osu! 官方设置说明](https://osu.ppy.sh/wiki/en/osu%21_tournament_client/osu%21tourney/Setup)
3. 关闭所选安装正在运行的 osu!。在「设置」点「生成 tournament.cfg」可单独写入配置，在「概览」点「打开 osu!Tourney」会写入配置并启动。配置写在所选程序旁，采用 4 人每队和高度 1080，`acronym` 自动填写当前授权赛季，例如授权 S12 时填 `OCLR S12`。如果替换了不同内容的旧配置，上一份文件会保存在同一目录的 `tournament.cfg.oclr.bak`。

在同一台电脑运行 osu!Tourney 和 tosu，让 tosu 读取本场房间。直播控制台使用启动窗口检测到的 tosu 端口接收游戏数据。重新选择 tosu 或修改 `SERVER_PORT` 后，控制台自动切换端口。如果没有有效端口，控制台会等待设置恢复。退出 OCLR 后，已打开的 osu! 和 tosu 可继续运行。

在「比赛现场」看 **Now Playing**。它随客户端换图，显示曲名和难度，能确定图池槽位时也会显示编号。直接播放热身图即可看到它，无需先做 Ban 或 Pick。

房间左右队名直接从 tosu 读取，无需选择“已核对”或手动填写。在“比赛配置 → 游戏数据”可以查看当前读数和三个自动跟随开关。自动跟随默认开启；收到有效赛事数据且房间已经 Playing 时即可中途加入，顶部可查看连接状态。

在图池选 Ban/Pick 或单独准备 TB。在 Playing 核对本图队分、胜方和系列比分，Ranking 继续使用同一画面。异常时从「处理异常」选择等待、恢复原局或裁判重赛。

## 4. 添加 OBS 浏览器源

### OBS 跟随 EX

Windows 启动器的「设置 → 比赛画面 → 高分辨率渲染」默认关闭。开启后，OCLR 管理的常规和 EX 比赛场景共用 3840×2160 浏览器源，并等比适配到 1920×1080 OBS 画布。切换会短暂刷新该浏览器源，宜在开播前或场间操作。

1. 在 OBS 的「设置 → 视频」将基础画布设为 1920×1080。在「工具 → WebSocket 服务器设置」启用服务和密码认证。打开 OCLR 控制台，在「比赛配置 → OBS」输入端口（默认 4455）和密码，点「连接本机 OBS」。
2. 核对本场常规人数为 4v4，并选择游戏源比例。点「创建比赛场景」。当前 OBS 场景集合会得到「OCLR · 常规 4v4」和「OCLR · EX 3v3」，两套场景共用置顶的观众画面和八个捕获源。误删其中一套或两套时，再点一次「创建比赛场景」即可补建缺失的布局。使用自建场景时，直接从两个列表选择并勾选「OBS 跟随 EX」。
3. 以 `TeamSize=4` 启动 osu!tourney，EX 时保持八个客户端。常规核对左侧红队 Client 0–3（A1–A4）、右侧蓝队 Client 4–7（B1–B4）。EX 开打前把上场选手排入 Client 0–2、4–6，并让 3、7 留空。EX 场景也使用这六路，已有自定义窗口绑定请按本场席位核对。Overlay 按这六路本局分数重新计算；如结算数据缺失，请按裁判核对的结果人工记胜。OBS 设置保存在本机用户数据目录的 `obs-settings.json`。 标有「未找到」或「有歧义」的槽位可补选窗口，重名窗口需要先处理。
4. 点「切回当前比赛布局」进入比赛。按原来的按钮开启或关闭 EX，OBS 会切到相应布局。红蓝双方交替开启 EX 时，六路布局保持原位。导播切去广告或休息后，在比赛现场的「OBS 节目画面」核对场景名和缩略图，再点旁边的「切回当前比赛布局」。

预设新放入的场景项默认锁定。需要调整位置时，在 OBS「来源」列表点该项的锁图标。常规与 EX 各自保存锁定状态，切换场景或重连 OCLR 后会保留你的选择。

Windows OBS 提供「应用程序音频采集」时，两套预设共用「OCLR · osu!tourney 音频」，自动按唯一窗口标题绑定 Tournament Client 0。EX 隐藏 Client 0 的视频时，音频来源仍启用。窗口缺失或重名时会等待并自动重新识别；设置中显示绑定状态。已有本项目预设会在重新连接后自动补齐，并停用两套比赛场景内由本项目创建的旧桌面音源；自建场景仍由导播管理。

OBS 不提供应用程序音频采集时保留旧桌面音频方式，并提示升级 OBS。播放一段游戏音乐，在 OBS 混音器检查对应音轨的电平与静音按钮。导播自行配置的全局桌面音频及其他音源保留；检测到全局桌面音频时会提示核对重复收音。Windows 实际有声、常规／EX 切换连续性与重音仍需直播机试听。

首次使用请打开 OBS 工作室模式并录制常规八路 → EX 六路 → 常规八路，逐窗核对 Playing 和 Ranking 中的选手和位置。到「核对 OBS 原始尺寸与位置」读取两套场景的数据。游戏捕获尚无画面时，OBS 可能报告宽高为 0，可在两套场景分别显示过画面后再读取。已在 OBS 手调的外部场景可直接绑定，按所选比例核对位置。本机自动创建的预设会随游戏源比例调整捕获矩形。

### B 站直播间弹幕

1. 用主播账号登录 B 站互动玩法，复制本直播间的「身份码」。[打开 B 站互动玩法](https://play-live.bilibili.com/) · [blive.chat 官方图文教程](https://blive.chat/help)
2. 在控制台打开「比赛配置 → OBS」，连接本机 OBS，将身份码粘贴到「B 站直播间弹幕」。如果还在准备场景，继续点「创建比赛场景」，或选好已有的常规与 EX 场景。下次换直播间时在同一处粘贴新码即可。
3. OCLR 在两套场景中共用一个「OCLR · 直播间弹幕」浏览器源，默认锁在右下角 **STREAM CHAT** 内。开播后在 OBS 预览或 Program 看一条实际观众弹幕，再切到另一套场景核对。左侧 **MATCH CHAT** 显示 osu! 房间聊天。

同一场景集合已有相同弹幕地址的浏览器源时会自动复用，Showcase 也共用它；未找到才新建。同名来源内容不同时会自动加编号，不需要手动改名。不同场景集合分别配置。

身份码随当前 OBS 场景集合保存在本机。OBS 使用含该码的房间地址连接 blive.chat，分享 OBS 场景集合前请隐去此来源地址。

### 手动添加观众画面浏览器源

在启动窗口点「复制 OBS 地址」，在 OBS 新建浏览器源。默认地址为 `http://127.0.0.1:3001/overlay`，宽 1920、高 1080，位置 (0,0)。关闭「不可见时关闭源」和「场景激活时刷新」。复用同一个源即可跟随比赛画面切换。

将各路游戏捕获放在浏览器源下方，按实际源比例对齐 Playing 的透明窗口。正式输出直接透出下方游戏，浏览器源无需色键。比赛进入 Ranking 时原位显示结算。

手动配置 3v3、4:3 时，每路宽 480、高 360，缩放 1:1，裁切为 0。按下表摆放；16:9 对应高度 270，各窗口在原行内垂直居中。

| 槽位 | 左队左上角 (x, y) | 右队左上角 (x, y) |
| --- | --- | --- |
| 第一路 | (0, 180) | (960, 180) |
| 第二路 | (480, 180) | (1440, 180) |
| 第三路 | (240, 540) | (1200, 540) |

### Showcase 回放过场

在 `/showcase` 的「OBS 场景」中连接 OBS、创建或打开已有 Showcase 场景，然后点「启用自动过场」；已启用旧版纯色遮挡时，点「更新过场美术」。将普通 osu! 客户端的捕获源放在 Showcase 背景源上方，并保持在中央 1600×800 区域内。最上层的「OCLR · Showcase 过场美术」浏览器源以 1920×1080 铺满画布，展示深紫斜幕、下一张谱面与图池进度。原有不透明遮挡保留在美术下方，负责加载和切换期间的回放区遮挡。

1. 在桌面「设置」选普通 osu!stable 的 `osu!.exe`，先启动普通客户端并让 tosu 读取它。推荐为 Showcase 使用独立的普通客户端目录，带 `tournament.cfg` 的安装用于比赛。开播前安装清单中的谱面。
2. 在桌面「Showcase」或浏览器 `/showcase` 的「演示图池」检查回放。网站导入后会读取清单，一份回放自动选中，多份时按文件名、玩家和 Mods 选择。缺件可把本地 `.osr` 拖到对应 Slot，或点「选文件」。本地补位保留到更换图池或退出直播服务。
   开播前点「提前缓存回放」，从下一张起预下载已选中的网站回放。看到「已缓存」就可以播放，失败的回放可再次点按钮重试。播放时会向网站核对当前授权和版本，随后使用本机文件。更换图池、重新连接授权或退出直播服务会清理网站缓存。
3. 在 OBS 将 Showcase 切到节目画面。等「遮挡已确认」后点「播放下一张」。若下一张缺件，补文件，或在已就绪的行点「设为下一张」。页面显示「等待 osu! 开始回放」，收到目标回放且时间推进后自动揭幕。
4. 回放结束后，成绩页展示 3.5 秒，随后遮挡自动盖上。再次确认遮挡后，可继续「播放下一张」或点「重播本张」。到清单末尾会停下。同图重播不会重复计入已播。
5. 回放打不开或打开了其他谱面时，核对当前 Slot 的回放、普通 osu! 和 tosu，然后原位重试。切到休息或广告后，先切回 Showcase 等待遮挡确认。需要手动接管时，在 OBS 核对画面，再点「确认画面安全，手动显示」。点「立即遮挡」恢复自动过场。

管理员仅授权图池时，请在 Showcase 授权中开启回放读取。补传或删除回放会更新图池版本。点「刷新回放」检查，如果提示图池已变化，请管理员重新授权图池和回放，然后在「从 OCLR 网站导入」重新选新版。

过场底栏将当前 Slot 固定居中，只显示前后各 3 张；首尾缺少的位置留空，右侧 Stream Chat 全程保留。图池进度只记录本次服务运行期间确认结束的回放，同图重播不重复增加；刷新网页保留，修改演示图池或重启服务后重新统计。没有封面时显示 Slot 色块。过场使用现有谱面卡的封面来源，不控制音频。

## 5. 结束、更新与找回比赛

在 OBS 停止录制后，到比赛现场展开「录像打点」，点击「复制时间轴」并与录像一起保存。录制中可点「标记精彩时刻」。[节目预览与录像操作](main-operator-contract.md#obs-节目画面与录像打点)

直播结束，在小窗口点“退出直播服务”并确认。OBS 网页输出会停止；再次双击会恢复已保存比赛。点窗口右上角关闭也会先确认。

### 资料存储与更新

默认使用 `%LOCALAPPDATA%\OCLR`。`StreamOverlay` 保存比赛、Showcase、OCLR 的 OBS 连接设置、归档、备份和录像时间轴。`StreamOverlayLauncher` 保存 tosu／osu! 路径（`settings.json`）、服务端口（`service-port.txt`）、启动日志及 WebView2 缓存。

希望资料随程序移动时，在桌面「设置 → 资料存储」点击「启用完全便携模式」。确认后，OCLR 保存比赛并退出，OBS 输出会中断。重新打开 OCLR 即可使用 `OCLR.exe` 旁边的 `OCLR-data`。首次启用会复制现有设置和比赛，Windows 用户目录中的原资料会保留。WebView2 缓存会在新位置重建；Showcase 回放的临时文件也会写入 `OCLR-data`。

切回 Windows 用户目录时，会恢复该目录中的资料；以后再次启用完全便携时，会恢复之前的 `OCLR-data`。两个位置各自保存进度。包内工具路径可随程序目录移动，位于程序目录外的工具仍使用其原路径。随包 tosu 的 `tosu.env` 仍位于 `tosu` 目录。OBS、系统浏览器和 osu! 自己的配置由相应程序管理。

更新时先退出旧版，再把新版解压到另一个目录。默认模式可直接启动新版；完全便携模式请把旧版的 **`OCLR-portable` 文件和 `OCLR-data` 目录**一起复制到新版 `OCLR.exe` 旁边。备份前请先退出 OCLR。当前存储位置可在桌面「设置 → 资料存储」查看。

启动日志为当前存储中的 `StreamOverlayLauncher/launcher.log`。达到 1 MiB 时保留上一份为 `launcher.log.1`。如需提供给维护者，请先检查是否包含私人资料。

从旧 Node 版本迁移：先正常退出旧服务，把旧项目的 `.local` 文件夹复制到新包的 `OCLR.exe` 旁边，再首次启动。程序先备份旧记录，再迁移；原文件保留。已有新数据时以用户数据目录为准，不自动覆盖。旧比赛若原本用其他地址，请把 OBS 源改为启动窗口当前显示的地址。以后修改服务端口时，连接 OBS 后会自动同步已识别的本机来源。

启动提示地址被占用或已有其他版本时，先退出原 OCLR 启动窗口或请维护者处理占用；程序不会改端口，也不会结束其他项目。记录无法读取时保留文件交给维护者检查，不要删除数据或初始化。

本包未做代码签名，Windows 可能显示发布者未知。请由维护者核对下载来源及随包校验值，不要关闭系统防护。随包的《验证状态.txt》记录历次验证的环境与范围。

| 看到的情况 | 怎么处理 |
| --- | --- |
| 网页误关了 | 在「OCLR 直播服务」窗口切到「直播控制台」，继续当前比赛。 |
| 桌面控制台未载入 | 点「重新加载页面」。也可点「在浏览器打开」，或从「设置 → 复制全部地址」取得控制台地址。 |
| 提示缺少运行文件 | 重新完整解压，保留 OCLR.exe 旁边的 app、runtime 文件夹，不要只复制 exe。 |
| tosu 没有当前读数 | 确认 tosu 与 osu!tourney 在同一台电脑运行，tosu 能提供当前赛事房间的 tourney 数据。 |
| OBS 画面没有变化 | 确认启动窗口仍运行，浏览器源使用 `/overlay` 地址且没有附加 `#scene`；不要把 `/control` 填进 OBS。 |
| 历史资料读取失败 | 检查网络，再看“维护详情 → 赛事资料”；不要拿空列表当作已成功加载。 |
| 地址被占用、已有旧版或数据无法读取 | 按启动提示联系维护者，保留数据文件；不要删除比赛来尝试修复。 |

便携版启动本身不需要联网下载运行时，线上历史资料读取需要联网。更详细的开发与验收状态见仓库的 `docs/verification/windows-portable/README.md`，分发包内也有“验证状态.txt”。

## 修改服务端口

默认使用 3001。在启动窗口的「设置」输入 1–65535 的整数，然后点击「重新启动 / 重试」。运行中的服务会要求确认暂时中断输出；程序先记住设置，再正常结束自己的服务并重新启动，比赛资料保持原目录。端口已被占用时可直接修改后重试，不会结束其他程序或自动跳到另一个端口。

「复制全部地址」依次提供控制台、Overlay 和 Showcase 地址。已连接 OBS 时，会自动检查当前场景集合中的本机 Overlay／Showcase 浏览器源并更新端口，保留网址参数、位置与尺寸；重连或切换场景集合时也会检查。手动来源识别默认 3001 与本机记录过的服务端口，已记录身份的预设来源也支持旧自定义端口。未连接 OBS 时，连接后自动同步。更换端口后重新连接 OCLR。端口保存在当前存储的 `StreamOverlayLauncher/service-port.txt`，更换 tosu 或 osu! 路径不会覆盖端口。
