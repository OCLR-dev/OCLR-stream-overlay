# Windows 便携版使用说明

适用：Windows 10 / 11，Intel 或 AMD 64 位（x64）。无需安装 Node.js、Git，不用输入命令。tosu、osu!tourney、OBS 由你自行安装运行，不包含在本包中。

> Pre-release 是通过 CI 打包与 Windows 原生启动检查的预览版本。开播前请核对该版本的实际 tosu／OBS 接线与播出效果。

## 1. 获取压缩包、解压、双击启动

1. 在 [GitHub Releases](https://github.com/OCLR-dev/OCLR-stream-overlay/releases) 选择所需提交的 Pre-release，从 Assets 下载 `OCLR-Windows-x64.zip`，右键“全部解压”。可用旁边的 `.zip.sha256` 核对下载内容。
2. 双击解压后的 **OCLR.exe**。等待“本机服务已就绪”，默认浏览器会打开直播控制台。
3. 保留“OCLR 直播服务”小窗口，可最小化。重复双击会打开同一个控制台，不会开第二场比赛。网页关了也没关系，点小窗口里的“打开控制台”即可。

## 2. 选择历史测试场次

进入“开播前设置 → 从 OCLR 已发布资料选择”，赛季填 **s10**。等待“S10 历史归档”载入后，选择 **Group A 1（match-1）** 场次和 **Group Stage 1（gs1）** 图池。此入口已验证可读取 S10；读取资料需要联网，失败时查看维护详情里的赛事资料提示。

历史资料只带入对阵和图池，**不带历史比分**；新测试从 **0:0** 开始。核对阶段、人数与上场名单。已有练习比赛需要清空时再点“初始化”：会先存档，误操作可撤销。中途重新开始可保留自动读取的房间连接，继续显示 Playing 与实时队分；不补记之前的赛果。

## 3. 连接 tosu

在启动窗口点击「选择 tosu…」，选取本机已解压的 tosu `.exe`，再点击「打开 tosu」。所选路径会记住，下次打开 OCLR 时可直接使用。移动或更新 tosu 后若原路径失效，重新选择新版程序即可。

启动窗口按所选 `.exe` 的完整路径检查程序是否运行，运行时会停用「打开 tosu」以避免重复启动。`127.0.0.1:24050` 单独显示端口连通状态。游戏数据是否就绪可在直播控制台查看。

在同一台电脑启动 osu!tourney，让 tosu 读取实际测试房间。控制台默认连接 `ws://127.0.0.1:24050/websocket/v2`。tosu 由自己的窗口管理，退出 OCLR 后可继续运行。

在「比赛现场」看 **Now Playing**。它随客户端换图，显示曲名和难度，能确定图池槽位时也会显示编号。直接播放热身图即可看到它，无需先做 Ban 或 Pick。

房间左右队名直接从 tosu 读取，无需选择“已核对”或手动填写。在“开播前设置 → 房间连接与自动跟随”可以查看当前读数和三个自动跟随开关。自动跟随默认开启；收到有效赛事数据且房间已经 Playing 时即可中途加入，顶部可查看连接状态。

图池可先选队伍 Ban/Pick 再点谱面，也可先点谱面再选动作，不要求补齐过去 BP；修改进行中或已打图的标记不改赛果。Playing / 单图结算还可直接准备当前局、校正系列比分和处理赛果；比分与设置修改后自动生效。异常时用“处理异常”，保留等待核对、观战恢复、裁判重赛、撤销和纠错。所有操作只保存本机，不向房间或 OCLR 网站写赛事数据。

## 4. 添加 OBS 浏览器源

### OBS 跟随 EX

1. 在 OBS 的「设置 → 视频」将基础画布设为 1920×1080。在「工具 → WebSocket 服务器设置」启用服务和密码认证。打开 OCLR 控制台，在「开播前设置 → OBS 场景联动」输入端口（默认 4455）和密码，点「连接本机 OBS」。
2. 核对本场常规人数为 4v4，并选择游戏源比例。点「创建比赛场景」。当前 OBS 场景集合会得到「OCLR · 常规 4v4」和「OCLR · EX 3v3」，两套场景共用置顶的观众画面和八个捕获源。误删其中一套或两套时，再点一次「创建比赛场景」即可补建缺失的布局。使用自建场景时，直接从两个列表选择并勾选「OBS 跟随 EX」。
3. 以 `TeamSize=4` 启动 osu!tourney，EX 时可继续使用这八个客户端。核对 A1–A4 对应左侧红队，B1–B4 对应右侧蓝队。标有「未找到」或「有歧义」的槽位可补选窗口；标题完全相同时请先关闭多余窗口。EX 初始采用两队各自前三路，可按实际上场阵容换成第四路。OBS 会保存窗口绑定，OCLR 将密码和场景集合的设置保存在本机用户数据目录的 `obs-settings.json`。
4. 点「切回当前比赛布局」进入比赛。按原来的按钮开启或关闭 EX，OBS 会切到相应布局。红蓝双方交替开启 EX 时，六路布局保持原位。导播切去广告或休息后，比赛现场会显示实际播出的场景名，再点「切回当前比赛布局」即可返场。

预设新放入的场景项默认锁定。需要调整位置时，在 OBS「来源」列表点该项的锁图标。常规与 EX 各自保存锁定状态，切换场景或重连 OCLR 后会保留你的选择。

两套预设都使用桌面音频。已有旧预设时，点一次「创建比赛场景」即可补上声音。OCLR 优先沿用 OBS 已配置的全局桌面音频，或预设里已启用的音频输出采集。如果两者都没有，会创建「OCLR · 桌面音频」，让两套场景共用 Windows 的默认播放设备。播放一段游戏音乐，在 OBS 混音器查看对应音轨的电平与静音按钮。使用独立声卡时，可在该来源的「属性」中选择 osu! 实际使用的播放设备。

首次使用请打开 OBS 工作室模式并录制常规八路 → EX 六路 → 常规八路，逐窗核对 Playing 和 Ranking 中的选手和位置。到「核对 OBS 原始尺寸与位置」读取两套场景的数据。游戏捕获尚无画面时，OBS 可能报告宽高为 0，可在两套场景分别显示过画面后再读取。已在 OBS 手调的外部场景可直接绑定，按所选比例核对位置。本机自动创建的预设会随游戏源比例调整捕获矩形。

### B 站直播间弹幕

1. 用主播账号登录 B 站互动玩法，复制本直播间的「身份码」。[打开 B 站互动玩法](https://play-live.bilibili.com/) · [blive.chat 官方图文教程](https://blive.chat/help)
2. 在控制台打开「开播前设置 → OBS 场景联动」，连接本机 OBS，将身份码粘贴到「B 站直播间弹幕」。如果还在准备场景，继续点「创建比赛场景」，或选好已有的常规与 EX 场景。下次换直播间时在同一处粘贴新码即可。
3. OCLR 在两套场景中共用一个「OCLR · 直播间弹幕」浏览器源，默认锁在右下角 **STREAM CHAT** 内。开播后在 OBS 预览或 Program 看一条实际观众弹幕，再切到另一套场景核对。左侧 **MATCH CHAT** 显示 osu! 房间聊天。

身份码随当前 OBS 场景集合保存在本机。OBS 使用含该码的房间地址连接 blive.chat，分享 OBS 场景集合前请隐去此来源地址。

### 手动添加观众画面浏览器源

在启动窗口点“复制 OBS 地址”，在 OBS 新建一个“浏览器”源：

- 地址：`http://127.0.0.1:3001/overlay`
- 宽 1920，高 1080。
- 不勾选“不可见时关闭源”和“场景激活时刷新”。

始终使用这一个源；控制台切画面会同步到输出。关闭控制台网页不会关闭服务。

手动添加时，将各路游戏捕获放在浏览器源下方，按下节的窗口尺寸与正式输出的透明区域对齐。真实测试时请核对结算时序和赛果，必要时在控制台纠错。


### 原尺寸选手画面（更新后的前端）

当 osu!tourney 为 `Height=1080`、3v3，现场测得每路 480×360。将六个“游戏捕获”放在 UI 浏览器源下方，保持原始尺寸、缩放 1:1、裁切为 0；浏览器源也保持 1920×1080、位置 (0,0)、缩放 1:1。直播 UI 会给游戏让出对应空间，不需要缩小选手画面。六路坐标见[原尺寸接线表](verification/chroma-key/README.md)。

捕获区域是纯绿色，不再显示占位文字。只给 UI 浏览器源添加“色值键 / Color Key”，选择绿色；使用逐像素色值键可避免色度键在队色边框附近留下绿边。不要给游戏捕获来源扣绿。等待、Playing、单图结算使用同一组位置，切画面不需要重新摆放六路来源。更新前端后，在 OBS 刷新浏览器源缓存。

谱面底栏直接读取当前有效的 tosu beatmap，即使未加入或绑定房间也能显示；实时队分与自动流程使用 tosu 自动提供的赛事房间数据。软件不会自动创建 OBS 游戏捕获来源。

## 5. 结束、更新与找回比赛

直播结束，在小窗口点“退出直播服务”并确认。OBS 网页输出会停止；再次双击会恢复已保存比赛。点窗口右上角关闭也会先确认。

更新时先退出旧版，再把新版解压到另一个目录，双击新版 OCLR.exe。**比赛数据在 `%LOCALAPPDATA%\OCLR\StreamOverlay`，不在程序目录里**；替换或移动程序不会清空数据。找数据时按 Win + R，粘贴这个路径并回车。备份前先退出直播服务，再复制整个数据文件夹，包含 session.json、archive 和 backups。

tosu 路径独立保存在 `%LOCALAPPDATA%\OCLR\StreamOverlayLauncher\settings.json`，更换便携包后仍可读取。

从旧 Node 版本迁移：先正常退出旧服务，把旧项目的 `.local` 文件夹复制到新包的 `OCLR.exe` 旁边，再首次启动。程序先备份旧记录，再迁移；原文件保留。已有新数据时以用户数据目录为准，不自动覆盖。旧比赛若原本用其他地址，首次转用本便携版需要把 OBS 源改为上面的固定地址，以后不再更换。

启动提示地址被占用或已有其他版本时，先退出原 OCLR 启动窗口或请维护者处理占用；程序不会改端口，也不会结束其他项目。记录无法读取时保留文件交给维护者检查，不要删除数据或初始化。

本包未做代码签名，Windows 可能显示发布者未知。请由维护者核对下载来源及随包校验值，不要关闭系统防护。当前 Windows 实机、真实 tosu / OBS 验收状态见随附的验证记录；Mac 测试不代表 Windows 验收。

## 常见问题

| 看到的情况 | 怎么处理 |
| --- | --- |
| 网页误关了 | 在“OCLR 直播服务”窗口点“打开控制台”，不要初始化比赛。 |
| 浏览器没有自动打开 | 等启动窗口显示就绪后，点“打开控制台”，或打开 `http://127.0.0.1:3001/control`。 |
| 提示缺少运行文件 | 重新完整解压，保留 OCLR.exe 旁边的 app、runtime 文件夹，不要只复制 exe。 |
| tosu 没有当前读数 | 确认 tosu 与 osu!tourney 在同一台电脑运行，tosu 能提供当前赛事房间的 tourney 数据。 |
| OBS 画面没有变化 | 确认启动窗口仍运行，浏览器源使用 `/overlay` 地址且没有附加 `#scene`；不要把 `/control` 填进 OBS。 |
| 历史资料读取失败 | 检查网络，再看“维护详情 → 赛事资料”；不要拿空列表当作已成功加载。 |
| 地址被占用、已有旧版或数据无法读取 | 按启动提示联系维护者，保留数据文件；不要删除比赛来尝试修复。 |

便携版启动本身不需要联网下载运行时，线上历史资料读取需要联网。更详细的开发与验收状态见仓库的 `docs/verification/windows-portable/README.md`，分发包内也有“验证状态.txt”。
