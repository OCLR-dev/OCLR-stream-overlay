# Windows 便携版使用说明

适用：Windows 10 / 11，Intel 或 AMD 64 位（x64）。无需安装 Node.js、Git，不用输入命令。tosu、osu!tourney、OBS 由你自行安装运行，不包含在本包中。

> 当前便携包已生成，但尚未完成 Windows 原生启动及真实 tosu／OBS 联调验收。请先用于测试，开播前由维护者完成现场验证。

## 1. 获取压缩包、解压、双击启动

1. 从赛事组织者或维护者处取得 `OCLR-Windows-x64.zip`，右键“全部解压”。GitHub 的“Download ZIP”是源码包，不能代替便携包；不要在压缩包里面运行。
2. 双击解压后的 **OCLR.exe**。等待“本机服务已就绪”，默认浏览器会打开直播控制台。
3. 保留“OCLR 直播服务”小窗口，可最小化。重复双击会打开同一个控制台，不会开第二场比赛。网页关了也没关系，点小窗口里的“打开控制台”即可。

## 2. 选择历史测试场次

进入“开播前设置 → 从 OCLR 已发布资料选择”，赛季填 **s10**。等待“S10 历史归档”载入后，选择 **Group A 1（match-1）** 场次和 **Group Stage 1（gs1）** 图池。此入口已验证可读取 S10；读取资料需要联网，失败时查看维护详情里的赛事资料提示。

历史资料只带入对阵和图池，**不带历史比分**；新测试从 **0:0** 开始。核对阶段、人数与上场名单。已有练习比赛需要清空时再点“初始化”：会先存档，误操作可撤销。中途重新开始可保留自动读取的房间连接，继续显示 Playing 与实时队分；不补记之前的赛果。

## 3. 连接 tosu

在同一台电脑启动 osu!tourney 和 tosu，让 tosu 读取实际测试房间。控制台默认连接 `ws://127.0.0.1:24050/websocket/v2`。

房间左右队名直接从 tosu 读取，无需选择“已核对”或手动填写。在“开播前设置 → 房间连接与自动跟随”可以查看当前读数和三个自动跟随开关。自动跟随默认开启；收到有效赛事数据且房间已经 Playing 时即可中途加入，顶部可查看连接状态。

图池 Ban / Pick 只改播出标记。准备本图、开打和赛果在 Playing / 单图结算管理；比分与设置修改后自动生效。异常时用“处理异常”，保留等待核对、观战恢复、裁判重赛、撤销和纠错。所有操作只保存本机，不向房间或 OCLR 网站写赛事数据。

## 4. 添加 OBS 浏览器源

在启动窗口点“复制 OBS 地址”，在 OBS 新建一个“浏览器”源：

- 地址：`http://127.0.0.1:3001/overlay`
- 宽 1920，高 1080。
- 不勾选“不可见时关闭源”和“场景激活时刷新”。

始终使用这一个源；控制台切画面会同步到输出。关闭控制台网页不会关闭服务。

游戏捕获仍需由维护者接线；更新后的原尺寸布局和纯绿区域见下节。打包本身不代表真实结算时序或整套 OBS 联调完成。自动结算仍有完整旧快照提前计胜的已知风险，真实测试时要核对赛果，必要时纠错。


### 原尺寸选手画面（更新后的前端）

当 osu!tourney 为 `Height=1080`、3v3，现场测得每路 480×360。将六个“游戏捕获”放在 UI 浏览器源下方，保持原始尺寸、缩放 1:1、裁切为 0；浏览器源也保持 1920×1080、位置 (0,0)、缩放 1:1。直播 UI 会给游戏让出对应空间，不需要缩小选手画面。六路坐标见[原尺寸接线表](verification/chroma-key/README.md)。

捕获区域是纯绿色，不再显示占位文字。只给 UI 浏览器源添加“色值键 / Color Key”，选择绿色；使用逐像素色值键可避免色度键在队色边框附近留下绿边。不要给游戏捕获来源扣绿。等待、Playing、单图结算使用同一组位置，切画面不需要重新摆放六路来源。更新前端后，在 OBS 刷新浏览器源缓存。

谱面底栏直接读取当前有效的 tosu beatmap，即使未加入或绑定房间也能显示；实时队分与自动流程使用 tosu 自动提供的赛事房间数据。软件不会自动创建 OBS 游戏捕获来源。

## 5. 结束、更新与找回比赛

直播结束，在小窗口点“退出直播服务”并确认。OBS 网页输出会停止；再次双击会恢复已保存比赛。点窗口右上角关闭也会先确认。

更新时先退出旧版，再把新版解压到另一个目录，双击新版 OCLR.exe。**比赛数据在 `%LOCALAPPDATA%\OCLR\StreamOverlay`，不在程序目录里**；替换或移动程序不会清空数据。找数据时按 Win + R，粘贴这个路径并回车。备份前先退出直播服务，再复制整个数据文件夹，包含 session.json、archive 和 backups。

从旧 Node 版本迁移：先正常退出旧服务，把旧项目的 `.local` 文件夹复制到新包的 `OCLR.exe` 旁边，再首次启动。程序先备份旧记录，再迁移；原文件保留。已有新数据时以用户数据目录为准，不自动覆盖。旧比赛若原本用其他地址，首次转用本便携版需要把 OBS 源改为上面的固定地址，以后不再更换。

启动提示地址被占用或已有其他版本时，先退出原 OCLR 启动窗口或请维护者处理占用；程序不会改端口，也不会结束其他项目。记录无法读取时保留文件交给维护者检查，不要删除数据或初始化。

本包未做代码签名，Windows 可能显示发布者未知。请由维护者核对下载来源及随包校验值，不要关闭系统防护。当前 Windows 实机、真实 tosu / OBS 验收状态见随附的验证记录；Mac 测试不代表 Windows 验收。

## 常见问题

| 看到的情况 | 怎么处理 |
| --- | --- |
| 网页误关了 | 在“OCLR 直播服务”窗口点“打开控制台”，不要初始化比赛。 |
| 浏览器没有自动打开 | 等启动窗口显示就绪后，点“打开控制台”，或打开 `http://127.0.0.1:3001/control`。 |
| 提示缺少运行文件 | 重新完整解压，保留 OCLR.exe 旁边的 app、runtime 文件夹，不要只复制 exe。 |
| tosu 没有当前读数 | 确认 tosu 与 osu!tourney 在同一台电脑运行，tosu 能提供当前赛事房间的 tourney 数据。 |
| OBS 画面没有变化 | 确认启动窗口仍运行，浏览器源使用 `/overlay` 地址且没有附加 `#scene`；不要把 `/control` 填进 OBS。 |
| 历史资料读取失败 | 检查网络，再看“维护详情 → 赛事资料”；不要拿空列表当作已成功加载。 |
| 地址被占用、已有旧版或数据无法读取 | 按启动提示联系维护者，保留数据文件；不要删除比赛来尝试修复。 |

便携版启动本身不需要联网下载运行时，线上历史资料读取需要联网。更详细的开发与验收状态见仓库的 `docs/verification/windows-portable/README.md`，分发包内也有“验证状态.txt”。
