仅用于 `test/custom-match`，工作区 `/Users/me/Documents/osu!tour/overlay-custom-match`。原工作区及 3007／24053 不参与测试；不操作 OBS。本分支与 main 分开维护并同步到远端；最新 Windows 包为 R4，包含本轮界面与自动房间队名更新。

## 启动与地址

```sh
npm run build
npm run custom
# 或：维护者需要隔离模拟信号时（两者不要同时启动）
npm run custom -- --simulate
```

控制台：http://127.0.0.1:3011/control 。只读输出：http://127.0.0.1:3011/overlay 。模拟器：http://127.0.0.1:24054/ ，仅在 `--simulate` 时存在。服务仅监听本机。若端口占用会拒绝启动，不抢占旧服务。工作区有独立运行租约，不与原工作区共用。

独立会话为 `.local/custom-match/session.json`，初始化前存入同目录 `archive/`；撤销与刷新恢复沿用原实现。损坏或非自定义会话拒绝覆盖。代码不加载 `.env.local`、OCLR Key 或赛事 API；本机 OCLR 代理返回 `OCLR_DISABLED_CUSTOM_MATCH`。依赖沿用已有锁文件，当前 worktree 的 `node_modules` 链接到原项目已有依赖，未安装或升级依赖，也未复制原比赛。

## 配置

在“开播前设置”直接填写赛事标题、左右（红／蓝）播出队名、自由阶段名称和明确奇数 BO。BO 支持 1–31，先赢目标为 `(BO + 1) / 2`；比分校验、菱形和系列结束同步。阶段名称不决定 BO。留空保持等待，无效值提示原因且保留上次有效值。已有局次时不能清空 BO，改小后不能低于现有比分。

名单、图片和队旗不是前置条件，空名单与队旗沿用已有占位。图池仍为每行 `标签 谱面ID 标题`，标题可省略；支持 NM／HD／HR／DT／FM／CA／TB 标签。修改立即同步，已引用条目不能删除。封面仍取匹配的 tosu 背景或 osu! 官方封面，参数仍由既有 tosu 链路提供；模拟参数明确标测试。未给出其他赛事 FM 裁判规则时不显示 OCLR 的 FM 限制文案。

展开“房间连接与自动跟随”，填写实际 WebSocket 地址。收到有效赛事数据后，左右队名直接读取 tosu，无需选择“已核对”或重复手填；播出队名和名单仍由赛事资料／人工设置管理。红队读取房间左侧，蓝队读取右侧。空地址或断线时等待，自动化意图保留。地址修改会重新连接，不需重启；进行中换源保留原有本局异常处理。Playing 实时队分、Ranking 总分、当前谱面和聊天共用现有链路；缺少图池或本局记录不阻止实时显示，未观察到有效开打的 Ranking 不补计胜。

## BP 格式

本场 MP5 已采用“双方各一次 Ban → 自动交替 Pick（无二轮 Ban）”，直接在 Mappool 点击队伍 Ban／Pick 即可，不需文本配置。首次两项 Ban 完成后单独选择先 Pick 方，后续自动交替。没有有效 tosu 时保持等待，可用选谱面后的人工补做入口完成真实动作。已有两项首 Ban 可以直接采用此流程，不清空记录。

其他规则仍可展开“本场 BP 规则”，每行 `动作 队伍`，修改停顿或失焦后自动生效。无默认顺序；资料缺失时等待，不套用 OCLR。

| 动作 | 含义 |
| --- | --- |
| `ban` | 真实 Ban 完成后立刻进入下一动作；Ban 槽按该队出现次序分配 |
| `pick` | 真实 Pick 后准备本图，等待有效开打与结束，才进入下一动作 |
| `alternate` | 只能放最后一行；从所写队伍开始按需交替 Pick，不用手工列完整场 |

队伍可以是 `red`／`blue`，也可以是 `ban-first`／`other-ban`、`pick-first`／`other-pick`。引用两类先手时，仍分别在 Roll 选择“先 Ban”和“先 Pick”，可为同一队。完整固定顺序可只写 ban / pick；用尽后明确等待，不自行补顺序。规则最多 40 行。

**以下仅为已验证的隔离测试配置，不是任何赛事正式规则**：先完成双方两轮 Ban，再交替 Pick，与现有 OCLR 插入第二轮 Ban 的顺序不同。

```text
ban ban-first
ban other-ban
ban ban-first
ban other-ban
alternate pick-first
```

规则在服务端生成当前与后续动作，胜方不改变轮换。未开始 BP 时可改规则；开始后冻结已执行顺序，使用现有“当前动作”和“纠错：修改后续 BP 顺序”，或撤销到开始前修改。显式队列纠错后不再自动补充交替 Pick；观察、画面和计胜仍保持原意图。

准备期改图只替换原 Pick；裁判重赛是同 Pick 的新尝试。结束与记胜分离，上一局待记录时可继续下一图。人工补做真实动作、空 Ban、播出标记、纠错和撤销沿用现有入口。后续真实 BP 已执行时，迟到重赛须先撤销后续动作。

沿用现有每队两个 Ban 槽、TB 禁 Ban／EX、同队 HD／HR／DT 不可重复 Ban（NM／FM 例外）等校验；本次不扩展赛事裁判规则。BO 大于 1 时，常规完成 `BO - 1` 图或到达赛点平分后等待核对 TB；BO1 可按明确规则正常准备并完成一图。TB 始终由裁判确认后单独准备，不消耗普通 Pick；达到先赢目标后停止执行 BP，Winner 仍由直播员展示。若赛事使用超出上述范围的规则，应先明确需求，不能用测试配置冒充已支持。
