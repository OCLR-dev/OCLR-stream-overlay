# 自定义赛事配置

Custom-Match 支持主办方自行录入 osu! 赛事资料。通用 Windows 包首次启动进入待配置的本地会话，升级时恢复该电脑保存的比赛。 [Windows 便携包](custom-match-windows.md)

## 启动与地址

```sh
npm run build
npm run custom
# 或：维护者需要隔离模拟信号时（两者不要同时启动）
npm run custom -- --simulate
```

控制台：http://127.0.0.1:3011/control 。只读输出：http://127.0.0.1:3011/overlay 。模拟器：http://127.0.0.1:24054/ ，仅在 `--simulate` 时存在。服务仅监听本机。若端口占用会拒绝启动，不抢占旧服务。工作区有独立运行租约，不与原工作区共用。

独立会话为 `.local/custom-match/session.json`，初始化前存入同目录 `archive/`；撤销与刷新恢复沿用原实现。损坏或非自定义会话拒绝覆盖。代码不加载 `.env.local`、OCLR Key 或赛事 API；本机 OCLR 代理返回 `OCLR_DISABLED_CUSTOM_MATCH`。

## 配置

在「比赛配置 → 本场资料」填写赛事标题、左右（红／蓝）播出队名、自由阶段名称和明确奇数 BO。BO 支持 1–31，先赢目标为 `(BO + 1) / 2`；比分校验、菱形和系列结束同步。阶段名称不决定 BO。留空保持等待，无效值提示原因且保留上次有效值。已有局次时不能清空 BO，改小后不能低于现有比分。

名单可后补。队伍横幅和赢图提示使用队名首字标识。图池仍为每行 `标签 谱面ID 标题`，标题可省略；支持 NM／HD／HR／DT／FM／CA／TB 标签。修改立即同步，已引用条目不能删除。封面仍取匹配的 tosu 背景或 osu! 官方封面，参数仍由既有 tosu 链路提供；模拟参数明确标测试。未给出其他赛事 FM 裁判规则时不显示 OCLR 的 FM 限制文案。

在「比赛配置 → 游戏数据」填写实际 WebSocket 地址。Windows 新会话默认使用启动器检测到的本机 tosu；切换到手填地址后即按该地址连接，旧会话沿用已保存的选择。收到有效赛事数据后，左右队名直接读取 tosu，无需选择“已核对”或重复手填；播出队名和名单仍由赛事资料／人工设置管理。红队读取房间左侧，蓝队读取右侧。空地址或断线时等待，自动化意图保留。地址修改会重新连接，不需重启；进行中换源保留原有本局异常处理。Playing 实时队分、Ranking 总分、当前谱面和聊天共用现有链路；缺少图池或本局记录不阻止实时显示，未观察到有效开打的 Ranking 不补计胜。

## OBS 节目画面与录像打点

- 连接 OBS 后，回到控制台查看「OBS 节目画面」。这里约每两秒更新节目场景名和缩略图，并显示推流与录制状态。工作室模式下以 Program 为准。休息或广告结束后，在缩略图旁点「切回当前比赛布局」。
- OBS 未连接时显示「Overlay 预览」。已连接但显示「暂时读不到画面」时，在 OBS 的 Program 监看。
- 在 OBS 开始录制。tosu 观察到房间从准备进入 Playing 时，直播服务自动标记开打或同图重赛。提前切画面或准备重赛时，时间轴会等游戏实际开始。全场结果确认时也会自动打点，包括表演赛平局。中途接入从下一次观察到的事件开始。关闭控制台网页期间，直播服务继续打点。
- 录制中点击「标记精彩时刻」。停录后展开「录像打点」，点击「复制时间轴」，用时间码在对应录像中定位。暂停录制期间跳过打点，重新开始录制会另起一组。「重新接入」表示服务在录制中恢复了 OBS 连接。
- 每场打点保存在会话数据目录的 `recording-timelines` 子目录。刷新或重启后，继续同一场即可查看。备份时把该目录与录像一起保留。

Windows OBS 两套比赛预设共用 Client 0 应用音频。在「比赛配置 → OBS」查看窗口绑定，在 OBS 混音器核对电平。准备状态下可预览固定 NM／HD／HR／DT 的参数，开打后切换到实际选手参数。

## BP 格式

采用「双方各一次 Ban → 自动交替 Pick（无二轮 Ban）」的赛事可直接选择这个 BP 预设，再在图池操作队伍的 Ban／Pick。首次两项 Ban 完成后单独选择先 Pick 方，后续自动交替。没有有效 tosu 时保持等待，可用选谱面后的人工补做入口完成真实动作。已有两项首 Ban 可以直接采用此流程，不清空记录。

自定义规则从 Pick 开始时，若房间已经选好首图，确认先 Pick 后会在准备状态稳定时自动应用。

其他规则仍可展开“本场 BP 规则”，每行 `动作 队伍`，修改停顿或失焦后自动生效。无默认顺序；资料缺失时等待，不套用 OCLR。

| 动作 | 含义 |
| --- | --- |
| `ban` | 真实 Ban 完成后立刻进入下一动作；Ban 槽按该队出现次序分配 |
| `pick` | 真实 Pick 后准备本图，等待有效开打与结束，才进入下一动作 |
| `alternate` | 只能放最后一行；从所写队伍开始按需交替 Pick，不用手工列完整场 |

队伍可以是 `red`／`blue`，也可以是 `ban-first`／`other-ban`、`pick-first`／`other-pick`。引用两类先手时，仍分别在 Roll 选择“先 Ban”和“先 Pick”，可为同一队。完整固定顺序可只写 ban / pick；用尽后明确等待，不自行补顺序。规则最多 40 行。

**以下仅为已验证的隔离测试配置，不是任何赛事正式规则**：先完成双方两轮 Ban，再交替 Pick，与现有 OCLR 插入第二轮 Ban 的顺序不同。

```text
ban ban-first
ban other-ban
ban ban-first
ban other-ban
alternate pick-first
```

规则在服务端生成当前与后续动作，胜方不改变轮换。未开始 BP 时可改规则；开始后冻结已执行顺序，使用现有“当前动作”和“纠错：修改后续 BP 顺序”，或撤销到开始前修改。显式队列纠错后不再自动补充交替 Pick；观察、画面和计胜仍保持原意图。

准备期改图只替换原 Pick；裁判重赛是同 Pick 的新尝试。结束与记胜分离，上一局待记录时可继续下一图。人工补做真实动作、空 Ban、播出标记、纠错和撤销沿用现有入口。后续真实 BP 已执行时，迟到重赛须先撤销后续动作。

沿用现有每队两个 Ban 槽、TB 禁 Ban／EX、同队 HD／HR／DT 不可重复 Ban（NM／FM 例外）等校验；本次不扩展赛事裁判规则。BO 大于 1 时，常规完成 `BO - 1` 图或到达赛点平分后等待核对 TB；BO1 可按明确规则正常准备并完成一图。TB 始终由裁判确认后单独准备，不消耗普通 Pick；达到先赢目标后停止执行 BP，Winner 仍由直播员展示。若赛事使用超出上述范围的规则，应先明确需求，不能用测试配置冒充已支持。

## 验证边界

[验证记录](verification/custom-match/README.md) 包含配置、非 OCLR BP、重赛、纠错、旧帧和八组窗口量测。合成信号通过真实本机 WebSocket 传输，**不是实际 osu!tourney／tosu 联调**。既有完整旧快照提前进入 Ranking 的两个时序风险仍存在；有异常时沿用现有核对／人工赛果入口。未操作真实房间或 OBS。


Windows 完整测试包、首次预装资料和搬迁步骤见 [Windows 测试包说明](custom-match-windows.md)。2026-11-07 用户确认 CA 与 FM 相同处理：图池及模拟读取明确标示的 NM 基准，Playing 使用有效选手实际参数范围；分类仍为 CA。旧会话无规则时可在控制台选择明确流程并无损接续，见 [MP5 修复验证](verification/mp5-live-fixes/README.md)。


Mappool Ban／Pick 按钮可不选谱面直接设置服务器待执行动作，随后等新的有效换图；普通播出标记仍独立。当前自定义版222项回归、OCLR主线204项回归及发布范围见验证记录。

## 2026-11-09 通用实现同步

主线通用实现已同步，详情见 [同步记录](verification/main-custom-sync/README.md)。热身开关与 main 一致：只影响正式比分和 EX 等内容的显示，房间观测、当前局与计胜继续；不能用热身开关阻止比赛记录。需要停住时使用明确暂停。

本图一经准备，房间随后换图不会自动替换本图；确认换图后从控制台明确重新准备，保留原 Pick 归属与后续 BP。Pick 展示仍为七秒，首次收到对应房间换图时重新计时，保存失败后自动重试。

旧 schema 1 会话首次读取时会先保留原文备份，再迁移到 schema 2，BO、阶段、规则、CA、连接地址与撤销历史均保留。损坏文件或非自定义赛文件仍拒绝打开。

开发可使用 `npm run watch -- --simulate`。隔离端口必须同时指定独立会话：`npm run watch -- --simulate --app-port 3012 --ws-port 24055 --session-file /path/to/test-session.json`。

## Showcase 回放清单

1. 先启动普通 osu!stable，并在「游戏数据」连接相应的 tosu。回放使用系统默认的 osu!stable 安装路径，也可在当前桌面控制台的「设置」选择普通 `osu!.exe`。请预先安装谱面。
2. 从控制台顶部进入「Showcase · 图池演示」，录入或复制演示图池，将本地 `.osr` 拖到对应行，或点「选文件」。补入的回放保留到更换图池或退出服务。
3. 在 Showcase 的 OBS 设置中创建场景并启用自动过场。将普通 osu! 游戏采集放在背景源与过场来源之间，将 Showcase 切到 OBS Program。看到「遮挡已确认」后点「播放下一张」。缺件可现场补入，或点其他已就绪行的「设为下一张」。已播的谱面可用「重播本张」再次播放。
