# MP5 Xronicle — Windows x64 测试包 R4（2026-10-30）

适用于 Windows 10 / 11 的 Intel / AMD 64 位电脑，已包含 Node.js 运行环境，无需安装开发工具。

## 更新与启动

1. 在旧版启动窗口点“退出直播服务”，再将 `MP5-Xronicle-Windows-x64-20261030-r4.zip` **全部解压到新文件夹**。不要在 ZIP 内启动，也不要只复制 exe。
2. 用原 Windows 用户双击 `MP5-Xronicle-Test.exe`，保留启动小窗口（可最小化）。网页关闭不影响服务。此前实机存在普通权限启动问题；若仍遇到该问题，可沿用此前管理员启动方式。R4 未声称修复此权限问题。
3. 控制台为 http://127.0.0.1:3011/control ，OBS 只读输出为 http://127.0.0.1:3011/overlay ，画幅 1920×1080。地址与旧版相同，更新后刷新控制台和 OBS 浏览器源。
4. **已有比赛无需初始化**。程序继续读取 `%LOCALAPPDATA%\OCLR\CustomMatchTest`，新包不会用初始配置覆盖现有比赛、比分或操作记录。
5. 启动 osu!tourney 和 tosu，在“开播前设置 → 房间连接与自动跟随”填写实际 WebSocket 地址，例如 `ws://127.0.0.1:24050/websocket/v2`。房间左右队名直接读取 tosu，无需再次手填或选择“已核对”。修改地址后自动重连。
6. 三个自动跟随开关保留原有设置。连接有效且房间已在 Playing 时可直接加入，缺少图池、Roll、BP 历史或本局记录不妨碍实时画面；未观察到有效开打的旧 Ranking 不补计胜。
7. 结束时在启动窗口点“退出直播服务”。不要删除数据目录或初始化比赛来排障。

## R4 更新

- 新头部样式，保留自定义赛事标题、阶段和 BO；移除重复说明小字。缺失的两侧总分显示 0。
- Ranking 显示双方总分；已保存本局成绩优先，实时读数仍检查来源新鲜度和谱面身份。
- 分差上移，色条只按绝对分差线性移动：25 万分铺满半条，双方总分同比增长不会改变相同分差的长度。
- 谱面 BG 铺满信息卡，左侧重复图池标签移除；已明确匹配图池时右侧显示完整标签，池外谱面不猜 NM／HR 分类。
- 谱面标题上方只保留一个带开启方的 EX 标签。
- 等待、Playing、单图结算保留原尺寸游戏捕获位置和纯绿区域。OBS 浏览器源位于游戏来源上方，色键只作用于 UI 浏览器源；原有 OBS 接线可沿用。
- 未启动 tosu 时继续等待和重连，保留比赛及自动化设置，不因失败的 WebSocket 递归退出。

## 初始资料与操作

首次启动使用 MP5 Xronicle、瑞士轮、BO9 先赢 5；左红“好麻烦啊......”，右蓝“我发现队友都玩osu”。预装 17 张图：NM5 / HD2 / HR2 / DT3 / FM2 / CA2 / TB1，单轮 Ban 后交替 Pick。先 Ban 与先 Pick 独立；CA 只保留分类，不推断实际模组要求。

首次启动的名单、实际 tosu 地址和先手仍需按现场填写；窗口人数、游戏源比例按现场检查。播出队名／名单与 tosu 房间实时队名分别管理，红队读取房间左侧、蓝队读取右侧。图池可先选动作再选谱面，也可反过来；中途加入不用补齐未知的历史 BP。游戏捕获仍由 OBS 配置，本包不获取选手视频。

已有比赛以用户数据目录为准。`app\match-template.json` 仅是首次配置；`比赛配置.json` 是随包配置副本，`图池录入.txt` 可用于人工录入。不要用模板覆盖进行中的 `session.json`。下一场使用控制台“初始化”（先存档、可撤销）；中途初始化可选择保留当前房间连接。

## 数据与验证边界

独立数据目录仍为 `%LOCALAPPDATA%\OCLR\CustomMatchTest`，不读取原 OCLR `StreamOverlay` 比赛或 OCLR 凭证。更新程序路径不改变比赛位置。迁移电脑时先退出两台服务，备份后复制整个 CustomMatchTest 文件夹，并在目标电脑检查实际 tosu 地址；目标已有比赛时先备份，避免覆盖。

本包默认连接现场 tosu，不内置或默认启动模拟器；只监听本机 3011，不向房间发送命令，不访问 OCLR 线上赛事。健康信息 http://127.0.0.1:3011/api/health 中的 label 应为 `MP5-Xronicle-Windows-x64-20261030-r4`。

源码已通过 222 项回归、类型检查与生产构建，包内后端在 Mac 的独立临时数据目录验证。此验证不等于运行 Windows exe；Windows 原生启动、权限问题及真实 osu!tourney／tosu 结算时序仍需实机复测。既有完整旧快照可能提前计胜的时序风险仍保留原有异常／人工赛果纠错入口。详细结果见随包“验证状态.txt”。
