# 直播授权与下一场资料（#1）

在控制台打开「本场设置 → 连接直播授权 · 下一场」，填写赛季，点击「打开直播授权页」。S11 使用 https://oclr.org/streaming/s11 。网站要求登录且具有当前有效的 Streamer 权限；Admin、Developer 或仓库权限不等同于直播授权。

1. 在网站选择与控制台地址栏完全相同的本机网址，例如 `http://127.0.0.1:3001`。复制网站仅显示一次的凭证。
2. 在控制台粘贴凭证并点击「连接授权」。输入框随即清空，凭证仅留在 Node 服务内存，不写文件、会话、浏览器存储、URL 或日志。关闭控制台不影响读取；重启服务后需重新连接。
3. 查看已指派的下一场、准确轮次、时间与公开图池。没有下一场即显示空；未公开的图池保持空，不用其他赛季补齐。
4. 先通过已有「初始化」存档当前比赛，再点击「使用这场对阵」。仅写本机会话，可通过已有撤销恢复。上场名单未包含在该 API 中，需人工核对录入；不导入网站赛果。支持网站明确的 osu! 3v3/4v4、先赢 6/7 图规则；未知、固定图数或其他规则会提示人工核对，不能从轮次名推测 BO。
5. 「断开连接」清除本机内存凭证和可选来源，不清空已确认本场，也不会撤销网站凭证。若需要撤销，请回到网站授权页操作。

Node 每 15 秒只发起一次串行 GET，空场次也维持网站一小时闲置租约，不能延长原网页登录期限。401/403 清空来源并停止；429 遵守 Retry-After；网络/5xx 和契约错误以 30/60/120 秒退避重试。确认的本场保留并提示来源不可用。轮询不修改已选队伍、阶段、BP、比分、图池或裁判决定。

实现为专用 `/api/streaming` 本机端点，不扩大 `/api/oclr` 白名单，不改现有 Developer Key 或匿名公开读取。POST 仅允许严格同源 JSON；GET 返回不含凭证的状态。`connect` 接受 `edition`、`token`、可选 `afterFixtureId`（UUID）。锚点仅控制读取顺序；控制台默认读取第一场未完成指派，不自动认定网站比赛已结束。导入请求包含当前会话版本和看到的 fixture ID；旧版本、来源过期、场次变更或已有比赛进度均拒绝。

上游使用 HTTPS、禁止重定向、不携带 cookies 或 Origin、8 秒超时、2 MiB 流式上限，验证 saved-read 1.4.0+ 与所用字段、对阵/阶段/图池关联后重新投影。来源只留内存；明确导入的公开资料随本机会话持久化，凭证不持久化。服务关闭、断开与换授权会取消旧请求，迟到响应不能恢复旧资料。

参考：[网站契约](https://github.com/OCLR-dev/OCLR-website/blob/main/docs/streaming-api.md)。本次不发行真实凭证、不授予角色、不部署；真实授权、tosu/OBS 播出仍需具备权限的直播员验收。
