# OCLR 登录与直播任务（#3）

在控制台「开播前设置 → OCLR 直播任务」填写赛季，点击「登录 OCLR 并连接任务」。网站要求真实 osu! 登录和当前有效的 Streamer 权限；Admin、Developer 或仓库权限不等同于直播授权。

1. 在弹出的 OCLR 网站登录，然后授权页面显示的赛季和本机控制台。授权完成后自动连接并关闭窗口，无需复制凭证。网站及 overlay 均需安装本次配套更新；这次 PR 不部署网站。
2. 控制台自动读取本人已指派且公开的直播任务。在「选择直播任务」切换场次即可预览，不改变本场。每页最多五项，可「查看更多任务」或「返回首批任务」。没有任务保持空；不会拿历史赛季补齐。
3. 先用已有「初始化」存档当前比赛，再点击「使用所选直播任务」。导入仅写本机会话，可撤销。已有 Roll/BP、图池、比分或开打记录不会被覆盖。缺少公开图池可稍后人工设置；API 不提供上场名单，请人工核对录入。
4. 网站明确提供的 osu! 3v3/4v4 和先赢 6/7 图规则会同步采用。网站未提供阶段/规则时仍可选取并导入任务，保留当前阶段及人数，明确提示待人工核对。固定图数或其他不支持规则仍提示人工核对，不能从轮次名猜 BO。
5. 「断开连接」清除本机内存凭证及任务来源，不清空已确认本场。撤销网站凭证需回到网站授权页；退出网站或撤销 Streamer 权限会在后续请求中失效。

## 手动复制备用

展开「手动复制授权（备用）」，打开 https://oclr.org/streaming/s11 或对应赛季，选择与地址栏完全相同的本机网址（默认网站允许 `http://127.0.0.1:3001`、`http://localhost:3001`），复制凭证并点击「使用复制的授权连接」。其他端口需由维护者在网站的 `OCLR_STREAMING_ORIGINS` 显式配置。

登录窗口被拦截、关闭、超过十分钟，或浏览器无法保留发起窗口时，控制台会提示重新登录或使用备用复制。凭证输入随即清空；不写文件、浏览器存储、日志、OBS URL 或持久化会话。关闭控制台不影响已有后台读取；重启本机服务后需要重新连接。

## 数据与授权边界

网站与控制台使用精确 origin、发起窗口和一次性随机 state 核对消息；state 由 Node 生成，十分钟有效且只能消费一次。凭证经短暂的消息/同源 JSON 请求交给 Node，只保存在服务内存；ack 后网站清除临时凭证。OAuth 仅保留受白名单限制、绑定 OAuth state 的本站连接路径，不接受通用 redirect。

Node 利用现有 `GET /api/v1/streaming/tournaments/{edition}/next?afterFixtureId=...` 顺序读取每页至多五项任务，15 秒后再刷新，一次只处理一个上游请求。每页最多五个请求，共用八秒取消期限。每个响应限制 2 MiB，验证 saved-read 1.4.0+、字段与关联后重新投影。HTTPS、禁止重定向、不发送 cookies 或 Origin。游标只改变读取顺序，不向网站保存进度或完成任务。

401/403 清空任务并停止，无匿名降级；429 遵守 Retry-After；网络/5xx、超时与契约错误退避 30/60/120 秒。每次刷新保留仍有效的任务选择，失效任务不再可选；已确认本场仍保留。轮询不修改本场队伍、阶段、BP、比分、名单或图池。

本机专用 `/api/streaming` POST 仅允许严格同源 JSON，不扩大 `/api/oclr` 的 Developer/public 白名单。`authorize` 开始登录；`complete-authorization` 消费一次性 state；`connect` 是手动复制备援；`select` 仅选取已读取任务；`page` 选择后续或首批；`import` 验证来源新鲜度、fixture ID 与会话版本。断开/换授权/关闭服务会取消旧请求，迟到响应不会恢复旧资料。

参考：[网站契约](https://github.com/OCLR-dev/OCLR-website/blob/main/docs/streaming-api.md)、网站配套 issue #616。真实 OAuth/Streamer/OBS、中文文案及部署由具备权限的使用者验收；不以合成浏览器测试代替。
